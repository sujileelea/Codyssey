> 과제의 축 = **시계열 요약을 시스템 프롬프트에 주입한 GPT 채팅** + **Firestore CRUD · 대화 기록** + **Render · Vercel 배포**. 아래 순서대로 따라 하면 필수 4기능과 보너스 2종이 모두 확인됨

## 4. 화면 시연

1. **채팅** — 예시 질문 "이번 달 관심도는 어때?" 클릭 → 점 세 개 로딩 + "데이터 요약을 넣어 답을 만드는 중…" → 답(2026-10 월평균 · 최근 값 근거) · 아래에 "요약 주입: 2021-10-24 ~ 2026-10-18 · 261개 · 토큰 N"
2. **요약 표시** — 오른쪽 패널: 기간 · 개수 · 평균/중앙값 · 최대/최소(날짜) · 단기/장기 추세 배지 · 미니 그래프. "AI에게 들어가는 시스템 프롬프트 보기" 를 펼치면 같은 수치가 프롬프트 글로 보임
3. **데이터 관리** — 탭 이동 → 날짜 · 값 · 메모 입력 → **추가** → "저장했습니다 — …" 문구 · 목록 맨 위 새 행 강조 · 지표 타일 '최신 값' 갱신. 행의 **수정** → 값 바꿔 저장 / **삭제** → "삭제 확인" 한 번 더
4. **데이터 반영 확인** — 채팅으로 돌아가 "최신 값은?" → 방금 바꾼 값으로 답함
5. **대화 기록** — 왼쪽 목록의 지난 대화 클릭 → 메시지 전체 재표시 · 주소에 `?c=<대화 ID>` (새로 고침해도 유지). **+ 새 대화** 로 비우기, 목록의 **삭제** 두 번
6. **대화 저장** — 새 대화에서 '자동 저장' 끄기 → 질문 → **대화 저장** → 제목 입력 → 목록에 추가(`POST /api/conversations`)

## 7. 스스로 설명하기 — 과제 목표 대응

| 질문 | 답의 요지 | 근거 위치 |
| --- | --- | --- |
| 시계열 분석 → 요약 → 서비스 활용 흐름은? | Firestore 의 점들을 날짜순으로 읽어 기간 · 개수 · 통계 · 추세를 계산 → 같은 요약을 API 응답 · 요약 패널 · 프롬프트 주입이 함께 씀 | `analysis.py` · `data_service.py` |
| 추세는 어떻게 판정했나? | 최근 4개 평균 vs 직전 4개 평균, ±5% 안 = 유지. 단기만 보면 7월 급락이 안 보여 13개 기준 장기 추세를 함께 넣음 | `analysis.trend()` |
| 라우터와 서비스를 왜 나눴나? | HTTP 형식과 업무 규칙을 분리 — 같은 요약 함수를 API · 채팅 · 도구 · MCP 가 재사용, 테스트는 서비스 조립만 바꿔 끼움 | `deps.py` · `tests/conftest.py` |
| Pydantic 을 왜 썼나? | 잘못된 입력을 핸들러 전에 422 로 차단, 서비스는 검증된 값만 다룸, Swagger 문서도 자동 | `schemas.py` · `errors.py` |
| Firestore 에 어떻게 저장 · 조회하나? | 컬렉션 2개, 날짜는 ISO 문자열 → `order_by("date")` · `where(date ==)`, 대화 목록은 `select()` 로 messages 제외 | `repositories.py` |
| 컨텍스트 주입의 원리는? | 모델은 내 데이터를 모름 → 매 요청 시 요약을 시스템 프롬프트에 글로 넣어 답의 근거로 삼게 함, 데이터가 바뀌면 다음 요약이 바뀜 | `chat_service.build_system_prompt()` |
| CORS · 환경 변수 · 키 관리가 왜 필요한가? | 프론트와 API 의 출처가 달라 허용 목록 필요, 같은 코드를 환경마다 다른 설정으로, 키가 공개 저장소에 들어가면 누구나 사용 | `main.py` · `config.py` · `render.yaml` |

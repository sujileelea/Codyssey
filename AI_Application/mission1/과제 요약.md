# 1. 미션 요약

> 흩어진 프롬프트를 담는 '집'을 Python 콘솔 프로그램으로 직접 만들고, Git·GitHub로 버전 관리까지 하는 것이 출발점

- GenAI·멀티모달·노코드 자동화 미션을 거치며 쌓인 수십 개의 프롬프트(텍스트 지시문·이미지 키워드·페르소나 설계안)가 메모장·노션·메신저에 파편화
- 이번 미션의 본질 = 프롬프트 관리 그 자체보다 **아이디어를 Python으로 동작하는 소프트웨어로 구현**하고 **Git으로 이력을 관리**하는 경험
- 변수·조건문·반복문·함수가 프로그램 안에서 어떻게 맞물리는지 체감 — 카테고리 분류·키워드 검색·즐겨찾기를 코드로 짜며 '데이터를 다루는 논리' 습득
- 기능 하나 완성할 때마다 커밋, 브랜치를 나눠 작업, GitHub에 공개 → "아이디어를 코드로 만들고 버전 관리까지 할 수 있는 사람"

# 5. 핵심 개념 정리

## 5-1. 데이터 구조

- **리스트(list)** — 프롬프트 전체를 순서 있게 담는 컨테이너 · 번호(인덱스+1)로 접근
- **딕셔너리(dict)** — 프롬프트 1건 = `{"title", "content", "category", "favorite"}` 키-값 쌍
- 예시

```python
prompts = [
    {"title": "블로그 글 작성 도우미", "content": "당신은 10년 경력의 전문 블로거입니다...", "category": "텍스트 생성", "favorite": True},
    {"title": "제품 썸네일 생성", "content": "다음 제품의 매력적인 썸네일 이미지를 생성해주세요...", "category": "이미지 생성", "favorite": False},
]
```

- **카테고리 예시**: 텍스트 생성 · 이미지 생성 · 영상 생성 · 페르소나 · 자동화 · 기타

## 5-2. Git 명령 — 본 미션에서 각 1회 이상 사용

| 명령 | 역할 | 이번 미션에서 쓰는 순간 |
| --- | --- | --- |
| `init` | 폴더를 Git 저장소로 시작 | 프로젝트 폴더 생성 직후 |
| `add` | 변경 파일을 스테이징 | 매 커밋 전 |
| `commit` | 스테이징된 변경을 이력으로 기록 | 기능 하나 완성할 때마다 (10회 이상) |
| `push` | 로컬 커밋을 원격(GitHub)에 업로드 | 첫 커밋 후, 이후 수시 |
| `pull` | 원격 변경을 로컬로 가져와 병합 | GitHub에서 README 수정 후 등 |
| `checkout` | 브랜치 전환·생성(`-b`) | 목록 기능 브랜치 생성·복귀 |
| `clone` | 원격 저장소를 통째로 복제 | 공개 샘플 저장소 1개 확인 |
| `merge` | 브랜치를 현재 브랜치에 병합 | 목록 기능 브랜치 → `main` |

## 5-3. 브랜치 작업 흐름 (프롬프트 목록 기능)

```text
main ──┬──────────────────────────────┬── merge feature/list ──▶
       └── checkout -b feature/list ──┘  (show_list 구현·커밋)
```

# 7. 제약 사항 (감점 주의)

- **Python 3.10 이상**
- **필수 요구사항은 외부 라이브러리 없이 기본 문법만** — `input` `print` 리스트·딕셔너리·조건문·반복문·함수
- 모든 코드를 한 곳에 몰아 넣지 않고 **기능별 함수 분리**
- **의미 있는 커밋 10개 이상** — 기능 단위로 나누고 커밋 메시지로 변경 의도 설명
- `init` `add` `commit` `push` `pull` `checkout` `clone` `merge` **각 1회 이상**
- 브랜치 생성·병합은 로컬에서 `checkout`·`merge`로 기록
- 이전 미션 프롬프트 **3개 이상** 기본 데이터로 등록

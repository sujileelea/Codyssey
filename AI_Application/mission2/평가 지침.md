# 평가 지침 — 국내 여행 추천 프로그램 (LLM + 지도 API)

> 과제의 두 축 = **여러 API 를 엮는 파이프라인**(LLM JSON → 장소 검색 → LLM 리포트) + **오류가 나도 멈추지 않는 프로그램**. 아래 9단계를 순서대로 따라 하면 모든 요구사항이 확인되고, 끝의 표가 평가 문항별 근거를 가리킴

- 코드: `travel-planner/` · 결과물: `travel-planner/results/` · 상세 기록 `실행 로그.md` · 설명 요약 `cheatsheet.md`
- 준비: Python 3.10 이상 · 인터넷 · Gemini API 키(무료) · Kakao REST API 키(무료)

---

## 1. 설치 · 키 설정

```bash
cd travel-planner
python3 -m pip install -r requirements.txt pytest
cp -n .env.example .env       # -n: 이미 있는 .env 를 덮어쓰지 않음 → GEMINI_API_KEY, KAKAO_REST_API_KEY 채우기
```

- Gemini: [aistudio.google.com](https://aistudio.google.com/) → Get API key
- Kakao: [developers.kakao.com](https://developers.kakao.com/) → 내 애플리케이션 → 앱 키 → **REST API 키** (JavaScript 키 아님) · **앱 설정 → 카카오맵 → 활성화 ON**

## 2. 입력 검증 · 키 미설정

| 명령 | 기대 |
| --- | --- |
| `python3 travel_planner.py -date 2026-13-01` | `usage:` + `날짜 형식이 올바르지 않습니다` 후 종료 (exit 2) |

## 3. 정상 실행 (실호출)

```bash
python3 travel_planner.py -date "2026-11-20"      # 샘플에 없는 날짜 → 3단계 모두 실제 호출
```

- 기대: `[1/3]` 추천 지역 3곳 → `[2/3]` 지역별 `맛집 5곳 검색 완료` → `[3/3] 리포트 생성 완료` → `완료! results/2026-11-20_travel_plan.md` (약 10초)
- 샘플 날짜(`2027-03-15` 등)로 실행하면 캐시가 먼저 동작함(5단계)

## 4. 결과물 확인

```bash
python3 -c "import json; r = json.load(open('results/2026-11-20_raw.json')); print(list(r['recommendation'])[:4], len(r['places']), r['errors'])"
# → ['recommended_city', 'weather', 'events', 'reason'] 3 []
```

| 파일 | 확인 항목 |
| --- | --- |
| `results/<날짜>_raw.json` | `recommendation` 최상위에 `recommended_city`(문자열) `weather`(문자열) `events`(1~3개 배열) `reason`(문자열) + 보너스 `recommended_cities`(3곳) · `places` 에 지역별 `name address category url x y` · `errors` 배열 |
| `results/<날짜>_travel_plan.md` | 첫 줄 `# <날짜> 국내 여행 추천 리포트` · `## 추천 지역` · 지역마다 `추천 이유 / 날씨 요약 / 행사·축제 / 맛집 추천 / 1일 일정 제안(오전·오후·저녁)` · 끝에 `## 오류 요약(errors)` |

- 리포트의 맛집은 raw JSON 의 `places` 에 있는 곳만 나옴(LLM 이 지어내지 않음). 필수 항목이 빠진 LLM 리포트는 프로그램이 거르고 데이터만으로 대체 리포트를 만듦

## 5. 보너스 — 복수 지역 · 캐싱

```bash
python3 travel_planner.py -date "2026-11-20"                 # 2회째
python3 travel_planner.py -date "2026-11-20" --cities 1      # 옵션이 다르면 캐시를 쓰지 않음
```

- 2회째 기대: `[캐시] results/2026-11-20_raw.json 발견 — ... 건너뜁니다` · `[1/3] 1차 추천 (캐시)` `[2/3] 맛집 검색 (캐시)` → 리포트만 재생성
- `--cities 1` 기대: `[캐시] ... 를 쓰지 않습니다 — 지역 수가 다름(저장 3곳 · 요청 1곳)` → 다시 호출
- `--no-cache` 를 붙이면 3단계 모두 다시 호출

## 6. 오류 처리 — 지도 API 인증 실패

```bash
KAKAO_REST_API_KEY=wrongkey python3 travel_planner.py -date "2026-12-24"
```

- 기대: `[캐시] ... 를 쓰지 않습니다 — 이전 실행에 맛집 검색 오류(AUTH_ERROR) 기록` → `[2/3]` 에서 `<지역>: 오류: 인증 실패(401). 키 설정을 확인하세요.` → `맛집 섹션은 '데이터 없음'으로 처리하고 계속 진행합니다.` → 나머지 지역은 `같은 키라 검색을 건너뜁니다` → `리포트 생성 완료` → 오류 요약 + 조치 안내
- `results/2026-12-24_travel_plan.md` 의 맛집 = `데이터 없음 (장소 검색 결과 0건)` · 원본 JSON `errors[0].type == "AUTH_ERROR"`

## 7. 오류 처리 — 파싱 재시도 1회 · 0건 · 대체 리포트 (오프라인)

```bash
python3 -m pytest tests -q          # 86 passed (웹 서버 테스트 포함 시 그 이상)
```

- 네트워크·키 없이 `requests` 를 가짜 응답으로 바꿔 검증 — 깨진 JSON → 실패 이유를 넣은 프롬프트로 **1회만** 재요청 · 2회 실패 → `PARSE_ERROR` · 0건 → `EMPTY_RESULT` + 직접 찾기 링크 · 리포트 LLM 503 → 1회 재시도 후 대체 리포트 · 네트워크 → `NETWORK_ERROR`
- 실제 출력 모양은 `실행 로그.md` §5·§6

## 9. 코드 구조 · README

| 파일 | 역할 |
| --- | --- |
| `travel_planner.py` | CLI — argparse · 결과 안내 · 종료 코드 |
| `pipeline.py` | `run()` — [1/3] 추천 → [2/3] 검색 → [3/3] 리포트 조립 · 캐시 판단 · 저장 |
| `llm_api.py` | Gemini **POST** — `recommend()`(스키마·검증·재시도 1회) · `write_report()`(필수 항목 검사) |
| `place_api.py` | 장소 검색 공통 창구 — 검색어 보정 · 호출 · 오류/0건 처리 |
| `place_kakao.py` · `place_naver.py` | 제공자별 **GET** 요청 모양·응답 정리 (`PLACE_PROVIDER` 로 교체) |
| `report.py` `errors.py` `net.py` `config.py` | 저장·대체 리포트 / `ErrorLog`·오류 유형·조치 안내 / 일시 오류 재시도 / `.env`·키 확인 |

- `README.md`: 개요 · 실행 방법 · API 키 설정 · 키 유출 주의 · 결과물 확인 · 오류 정책 · 구조 · GET/POST · 테스트
- 모든 API 호출·파싱은 `try-except` (`grep -n "except" llm_api.py place_api.py pipeline.py`)

# 평가 지침 — 국내 여행 추천 프로그램 (LLM + 지도 API)

> 과제의 두 축 = **여러 API 를 엮는 파이프라인**(LLM JSON → 장소 검색 → LLM 리포트) + **오류가 나도 멈추지 않는 프로그램**. 아래 8단계를 순서대로 따라 하면 모든 요구사항이 확인됨

- 코드: `travel-planner/` · 결과물: `travel-planner/results/` · 상세 기록 `실행 로그.md`
- 준비: Python 3.10 이상 · 인터넷 · Gemini API 키(무료) · Kakao REST API 키(무료)

---

## 1. 설치 · 키 설정

```bash
cd travel-planner
python3 -m pip install -r requirements.txt
cp .env.example .env          # GEMINI_API_KEY, KAKAO_REST_API_KEY 채우기
```

- Gemini: [aistudio.google.com](https://aistudio.google.com/) → Get API key
- Kakao: [developers.kakao.com](https://developers.kakao.com/) → 내 애플리케이션 → 앱 키 → **REST API 키** (JavaScript 키 아님) · **앱 설정 → 카카오맵 → 활성화 ON**
- 확인: `git status` 에 `.env` 가 나오지 않음(`.gitignore`), 코드에서 `grep -rn "AIza\|KakaoAK [0-9a-f]" *.py` 결과 없음

## 2. 입력 검증 · 키 미설정

| 명령 | 기대 |
| --- | --- |
| `python3 travel_planner.py -date 2026-13-01` | `usage:` + `날짜 형식이 올바르지 않습니다` 후 종료 (exit 2) |
| `python3 travel_planner.py` | `-date/--date` 필수 안내 후 종료 |
| `mv .env .env.bak && python3 travel_planner.py -date 2026-10-03` | `API 키가 설정되지 않았습니다` + 설정 방법 안내 후 종료 (exit 1) → `mv .env.bak .env` 로 복구 |

## 3. 정상 실행

```bash
python3 travel_planner.py -date "2026-10-03"
```

- 기대: `[1/3]` 추천 지역 3곳 → `[2/3]` 지역별 `맛집 5곳 검색 완료` → `[3/3] 리포트 생성 완료` → `완료! results/2026-10-03_travel_plan.md`
- 이미 들어 있는 샘플과 같은 날짜라 캐시가 먼저 동작함(4단계). 새로 호출해 보려면 `--no-cache` 또는 다른 날짜

## 4. 결과물 확인

| 파일 | 확인 항목 |
| --- | --- |
| `results/<날짜>_raw.json` | `recommendation` 에 `recommended_city` `weather` `events`(1~3) `reason` + `recommended_cities`(3곳) · `places` 에 지역별 `name address category url x y` 5건 · `errors: []` |
| `results/<날짜>_travel_plan.md` | 첫 줄 `# <날짜> 국내 여행 추천 리포트` · 지역마다 `추천 이유 / 날씨 요약 / 행사·축제 / 맛집 추천 / 1일 일정 제안(오전·오후·저녁)` · 끝에 `## 오류 요약(errors)` |

- 리포트의 맛집은 raw JSON 의 `places` 에 있는 곳만 나옴(LLM 이 지어내지 않음)

## 5. 보너스 — 캐싱

```bash
python3 travel_planner.py -date "2026-10-03"              # 2회째
```

- 기대: `[캐시] results/2026-10-03_raw.json 발견 — ... 건너뜁니다` · `[1/3] 1차 추천 (캐시)` `[2/3] 맛집 검색 (캐시)` → 리포트만 재생성
- `--no-cache` 를 붙이면 3단계 모두 다시 호출

## 6. 오류 처리 — 지도 API 인증 실패

```bash
KAKAO_REST_API_KEY=wrongkey python3 travel_planner.py -date "2026-12-24" --cities 1
```

- 기대: `오류: 인증 실패(401). 키 설정을 확인하세요.` → `맛집 섹션은 '데이터 없음'으로 처리하고 계속 진행합니다.` → 리포트 생성 완료 · `오류 1건`
- `results/2026-12-24_travel_plan.md` 의 맛집 = `데이터 없음 (장소 검색 결과 0건)`, 오류 요약에 `` `place_search` · `AUTH_ERROR` — HTTP 401 ``
- `results/2026-12-24_raw.json` 의 `errors[0].type == "AUTH_ERROR"` (제출 샘플이 이 케이스)

## 7. 오류 처리 — LLM JSON 파싱 재시도 1회 · 대체 리포트 (오프라인)

```bash
python3 -m pytest tests -q          # 11 passed
```

- 네트워크·키 없이 `requests` 를 가짜 응답으로 바꿔 검증 — 파싱 실패 → **1회만** 재요청(프롬프트에 "필수 키만 다시 출력" 추가) · 2회 실패 → `PARSE_ERROR` · 리포트 LLM 429 → 데이터만으로 대체 리포트 · 0건 `EMPTY_RESULT` · 네트워크 `NETWORK_ERROR`

## 8. 코드 구조 · README

| 파일 | 역할 |
| --- | --- |
| `travel_planner.py` | argparse · 3단계 파이프라인 · 캐시 · 저장 |

| `report.py` `config.py` `errors.py` | 저장·대체 리포트 / .env 로드·키 확인 / `ErrorLog`·오류 유형 |

# 1. 미션 요약

> LLM API 와 지도 API 를 **엮어서** 국내 여행 추천 리포트를 만드는 CLI 프로그램 — 단일 호출이 아니라 여러 API 의 데이터를 조합해 인사이트를 도출

- 사용자가 여행 날짜 입력 → LLM 이 그 시기에 좋은 지역 추천(JSON) → 지도 API 로 맛집 검색 → LLM 이 최종 여행 리포트(Markdown) 생성
- 본질 = **LLM 출력을 구조화(JSON)** 해서 다음 단계 입력으로 연결하는 흐름 + 외부 API 오류(인증/쿼터/네트워크/파싱)에도 멈추지 않는 프로그램
- 날씨·행사 정보의 "정확도"를 평가하는 미션이 아님 — 중요한 건 구조화된 출력과 단계 간 연결
- API 키는 코드에 쓰지 않고 `.env`/환경변수로 관리

# 2. 과제 목표
> 수료 후 스스로 설명할 수 있다!

- REST API 의 요청/응답 구조와 HTTP 메서드(GET/POST)의 차이
- LLM 출력을 JSON 으로 구조화해 다음 단계(지도/장소 검색) 입력으로 쓰는 흐름
- 외부 API 대표 오류(인증/쿼터/네트워크/파싱)와 대응 원칙
- API 키를 코드에 직접 쓰지 않고 `.env`/환경변수로 관리하는 이유

# 4. 산출물별 필수 포함 항목 (체크리스트)

## 4-1. CLI 인터페이스

- [ ] `argparse` 로 실행
- [ ] 필수 옵션 `-date "YYYY-MM-DD"`
- [ ] 날짜 형식이 틀리면 사용법 출력 후 종료

## 4-2. API 제공자 (택1)

| 종류 | 후보 | 선택 |
| --- | --- | --- |
| LLM | OpenAI 계열 · **Google Gemini 계열** | Gemini 무료 티어 `gemini-3.5-flash-lite` (팀 프로젝트와 동일 키) |
| 지도/장소 | **Kakao Local**(키워드/카테고리) · Naver Local Search | Kakao Local 키워드 검색 — 응답 필드 `place_name` `address_name` `category_name` `place_url` `x` `y` 가 요구 필드와 1:1 |

- 다른 제공자를 쓸 때의 공통 조건: 국내 장소 검색 가능 · JSON 응답 · 최소 필드 `place_name` `address` `lat/lng`(또는 `x/y`) `url`(가능하면)

## 4-3. LLM 연동 — 1차 추천 (날씨/행사)

- [ ] 입력 = `date`, 출력 = **JSON 으로 파싱 가능한 텍스트**가 나오도록 프롬프트 설계
- [ ] 최소 스키마 — `recommended_city: string` · `weather: string` · `events: string[]`(1~3개) · `reason: string`(2~4문장)

## 4-4. 지도/장소 연동 — 맛집 검색

- [ ] 입력 = 1차 JSON 의 `recommended_city`, 출력 = 맛집 N곳(권장 5)
- [ ] 아이템 최소 필드 — `name` `address` `category`(가능하면) `url`(가능하면) `x,y` 또는 `lat,lng`(가능하면)
- [ ] 인증: Kakao 는 `Authorization: KakaoAK <키>` 헤더 (401/403 → 키·권한·도메인 점검) · Naver 는 Client ID/Secret 헤더 (401/403 → 키·헤더명 오타 점검)
- [ ] 결과 0건이어도 중단하지 않고 "데이터 없음" 으로 리포트 생성 진행

## 4-5. LLM 연동 — 최종 리포트

- [ ] 입력 = 1차 추천 JSON + 맛집 목록(0건 가능), 출력 = Markdown
- [ ] 포함 항목 — 추천 지역 + 추천 이유 요약 · 날씨 요약 · 행사/축제 목록 · 맛집 리스트(0건이면 "데이터 없음") · 1일 일정 제안(오전/오후/저녁)

## 4-6. 에러 처리

- [ ] `try-except` 로 API 호출/파싱 오류 처리
- [ ] 키 미설정 → 즉시 종료 + 설정 방법 안내
- [ ] 지도 API 실패(네트워크/인증/쿼터) → 맛집 "데이터 없음" 처리 후 리포트 생성 계속
- [ ] LLM JSON 파싱 실패 → 재요청 1회 또는 "필수 키만 다시 JSON" 프롬프트 수정 재시도 **1회** (무한 재시도 금지)
- [ ] 오류 목록을 내부 관리 → 리포트 `errors` 섹션 (빈 리스트 가능)

## 4-7. API 키 관리 · 결과 저장

- [ ] 키를 코드에 쓰지 않음 · 환경변수 또는 `.env`(python-dotenv) 에서 읽기 · README/로그/결과 파일에 키 노출 금지
- [ ] `results/` 폴더 생성, 날짜 기준 파일명
- [ ] 원본 JSON = 1차 추천 JSON(파싱 결과) + 맛집 검색 결과(0건 가능) + `errors: array`
- [ ] 최종 리포트 = `.md`

# 5. 핵심 개념 정리

## 5-1. REST 요청/응답 — GET 과 POST

| | Kakao Local (장소 검색) | Gemini (생성) |
| --- | --- | --- |
| 메서드 | **GET** — 조회. 검색어·개수를 URL 쿼리스트링에 | **POST** — 프롬프트·생성 설정을 요청 **본문(JSON)** 에 |
| 인증 | 헤더 `Authorization: KakaoAK <REST 키>` | 헤더 `x-goog-api-key: <키>` |
| 응답 | JSON `documents[]` — `place_name` `address_name` `category_name` `place_url` `x` `y` | JSON `candidates[0].content.parts[0].text` |

## 5-2. LLM 출력 구조화 → 다음 단계 입력

```text
프롬프트("JSON 만 출력") + responseMimeType=application/json + responseSchema
   → 텍스트 → json.loads → 필수 키·타입 검사 → recommended_city → Kakao 검색어 "<city> 맛집"
```

- 파싱 실패 시 "필수 키만 담은 순수 JSON 을 다시 출력" 으로 프롬프트를 고쳐 **1회만** 재시도

## 5-3. 대표 오류와 대응 원칙

| 유형 | 신호 | 대응 |
| --- | --- | --- |
| 인증 `AUTH_ERROR` | 401/403 (Gemini 는 400 "API key not valid") | 키 값·헤더명·권한(카카오맵 활성화) 점검. 재시도 무의미 |
| 쿼터 `QUOTA_ERROR` | 429 | 호출 줄이기·캐시·시간 두고 재시도 |
| 네트워크 `NETWORK_ERROR` | 연결 실패·타임아웃 | 타임아웃 설정, 실패해도 다음 단계 진행 |
| 파싱 `PARSE_ERROR` | JSON 아님·필수 키 없음 | 프롬프트 수정 재시도 1회, 스키마 검사 |
| 0건 `EMPTY_RESULT` | `documents: []` | "데이터 없음" 으로 계속 진행 |

- 원칙 = 실패한 단계만 격리하고 **리포트는 항상 만든다**, 오류는 `errors` 에 남긴다

## 5-4. 키를 .env/환경변수로 관리하는 이유

- 협업·공유 시 실수로 키 공개 방지 · 키 교체 시 코드 수정 불필요(운영/배포 유리) · 과금·쿼터 서비스 사고 예방
- `.gitignore` 에 `.env` 제외, 템플릿은 `.env.example` 로만 공유

# 6. 제약 사항 (감점 주의)

- **Python 3.10 이상**, 터미널 실행 (웹 UI 불요)
- **보안(필수)**: 키를 코드/README/결과물에 쓰지 않음 · `.env` 또는 환경변수
- 키 미설정이면 즉시 종료 + 안내 · 지도 API 실패에도 리포트 생성 · LLM JSON 재시도 **최대 1회**

# 7. 보너스 과제 (선택)

- **복수 지역 추천**: `recommended_cities: [..]` 2~3곳, 지역마다 맛집 검색, 리포트에 지역별 정리 — 반복 처리 + API 요청 관리 + 결과 구조 설계
- **결과 캐싱**: 같은 `-date` 재실행 시 저장된 원본 JSON 이 있으면 API 호출 건너뛰고 리포트 재생성 — 외부 API 비용/속도 최적화

# 8. 결과 예시 (참고용 — 정답 아님)

```text
$ python travel_planner.py --date "20XX-03-15"
[1/3] 1차 추천 생성 중(LLM)...
  - recommended_city: "제주"
[2/3] 맛집 검색 중(지도/장소 API)...
  - 맛집 5곳 검색 완료
[3/3] 최종 리포트 생성 중(LLM)...
  - 리포트 생성 완료
완료! results/20XX-03-15_travel_plan.md 를 확인하세요.
```

```json
{"recommended_city": "제주", "weather": "3월 중순 평균 15°C 내외, 바람이 있으나 비교적 온화함",
 "events": ["유채꽃 관련 지역 행사", "봄 시즌 지역 축제(예: 일정 변동 가능)"],
 "reason": "3월 중순은 제주가 봄꽃을 즐기기 좋은 시기입니다. ..."}
```

- 검색 0건: `- 검색 결과 0건(키워드/카테고리를 바꿔 재시도하지 않고 다음 단계로 진행)` → 리포트 `## 맛집 추천` 아래 `- 데이터 없음 (장소 검색 결과 0건)` → `errors: [{"step": "place_search", "type": "EMPTY_RESULT", "message": "0 results for query=..."}]`
- 인증 실패: `- 오류: 인증 실패(401). 키 설정을 확인하세요.` `- 맛집 섹션은 '데이터 없음'으로 처리하고 계속 진행합니다.` → `errors: [{"step": "place_search", "type": "AUTH_ERROR", "message": "HTTP 401"}]`
- 리포트 형식: `# 20XX-03-15 국내 여행 추천 리포트` → `## 추천 지역` `## 추천 이유` `## 날씨 요약` `## 행사/축제` `## 맛집 추천` `## (선택) 1일 일정 제안` `## 오류 요약(errors)`

# 9. 제출 전 최종 점검

- [ ] `-date` 형식 오류·누락 시 사용법 출력 후 종료 · 키 미설정 시 안내 후 종료

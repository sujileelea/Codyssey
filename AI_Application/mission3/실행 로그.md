## 2. 로컬 실행 · 오류 경로

```text
$ python3 scripts/dev_server.py
AITAG 시연 로컬 서버: http://localhost:3000  (GEMINI_API_KEY 설정됨)

$ curl -s -o /dev/null -w '%{http_code}' localhost:3000/            → 200  (demo/matrix/faq.html · css · js 모두 200)
$ curl -s localhost:3000/api/options | jq '.defaults'
{"domain":"ecommerce","content_type":"product","image_kind":"photo","category":"general","tone":"plain","length":"standard","language":"ko"}

# 빈 입력 (키 없이 실행한 상태)
$ curl -s -X POST localhost:3000/api/alt_text -d '{}'
{"error": "NO_API_KEY", "message": "서버에 GEMINI_API_KEY 가 설정되지 않았습니다. 운영자에게 문의하세요."}   [500]
$ curl -s localhost:3000/api/alt_text
{"error": "METHOD_NOT_ALLOWED", "message": "POST 로 이미지를 보내 주세요."}   [405]
```

- 브라우저 실패 안내 3종: 사진 없이 생성 → "사진을 올려 주세요…" (요청 미발송) · 4xx/5xx → 서버 `message` + 코드 표시 · 30초 초과 → "응답이 30초 안에 오지 않았습니다…" (`AbortController`)

## 3. 실호출 — 샘플 3종 (로컬, 실키)

| 샘플 | 매트릭스 키 | 소요 | alt_text (앞부분) |
| --- | --- | --- | --- |
| 행사 포스터 | `public.notice.poster.event.formal` | 2.8s | "2026 시민 접근성 워크숍 안내 포스터입니다. 2026년 10월 24일 토요일 오후 2시부터 5시까지 서울시청 시민청 태평홀에서 열립니다." |
| 식품 라벨 | `ecommerce.product.product_detail_image.food.plain` (detailed) | 2.3s | "우리밀 통밀 크래커 1봉 150그램 제품 정보 표" + long_description 에 원재료·알레르기 표시 원문 보존 |
| 인포그래픽 | `education.lecture.infographic.general.friendly` | 2.5s | "2025년 사이트 유형별 대체텍스트가 있는 이미지 비율을 나타낸 막대그래프예요. 공공기관이 78퍼센트로 가장 높고…" |

- 세 건 모두 `detected_text` 에 이미지 안 문구 전문, `is_decorative: false`, `replaced: []`
- **AI 코드 오류를 직접 고친 예 1** — 첫 실호출에서 인포그래픽 결과가 숫자까지 한글로 풀어 씀("이천이십오년", "칠십팔 퍼센트"). 원인 = 한국어 블록의 "단위·약어 풀어쓰기" 규칙을 모델이 숫자에도 적용. 수정 = "숫자는 아라비아 숫자 그대로, 단위 기호·영문 약어만 풀어쓰기"로 블록 문구 변경 → 재호출 "78퍼센트" 정상 (커밋 `f2bb60c`)
- **예 2** — 로컬 실행기의 `/api` 위임이 빈 응답. 원인 = `handler.do_POST(self)` 처럼 다른 클래스의 메서드에 요청 객체를 넘겨 `_json` 헬퍼를 못 찾음(`AttributeError`). 수정 = 요청 객체의 클래스를 api 핸들러로 바꿔(`self.__class__ = cls`) 그 클래스의 메서드를 그대로 실행

## 5. Vercel 배포

```text
$ vercel link --yes --project aitag-demo        → Linked to sujileelea/aitag-demo
$ … | vercel env add GEMINI_API_KEY production   → 값은 stdin 으로(명령줄·로그 미노출) · env ls: Encrypted · Production
$ vercel deploy                                  → 1차 실패: "No python entrypoint found … found api/alt_text.py (variable: handler)"
```

- **배포 오류를 직접 고친 예 3** — Vercel 이 `requirements.txt` 를 보고 프로젝트를 **Python 프레임워크 프리셋**으로 자동 감지 → 최상위 `app.py` 류 진입점을 찾고 `api/` 파일 함수를 무시. 수정 = `vercel.json` 에 `"framework": null` 추가(프리셋 해제 → 파일 기반 함수) → 재배포 성공 (커밋 `774c09c`)

```text
$ vercel deploy   → https://aitag-demo-39srjvjx2-sujileelea.vercel.app  (프리뷰 · Vercel Authentication 보호로 팀원만 접근)
프로덕션 도메인: https://aitag-demo-gamma.vercel.app  (`vercel --prod` — owner 결정 대기)
```

- 프리뷰 URL 은 Vercel 기본 배포 보호(로그인 필요) 때문에 비로그인 curl 은 302 → 공개 검증은 프로덕션 배포 후 수행
- **GitHub ↔ Vercel 자동 배포 연결**: `vercel git connect` → `400 You need to add a Login Connection to your GitHub account first`. Vercel 계정에 GitHub 로그인 연결이 없어 **owner 가 대시보드에서** ① Account → Login Connections → GitHub 연결 ② 프로젝트 Settings → Git → `sujileelea/Codyssey` 연결 ③ Settings → General → **Root Directory** `AI_Application/mission3/aitag-demo` · Framework Preset **Other** ④ Production Branch `main`. 연결 후엔 `main` push = 프로덕션, `develop` push = 프리뷰(`vercel.json` `ignoreCommand` 가 이 폴더 변경 없는 push 의 빌드를 생략)

# 1. 미션 요약

> AI 코딩 도구로 **나만의 웹 서비스**를 만들고, 전 세계 누구나 접속할 수 있는 **Vercel URL** 로 배포한다. 방문자가 실제로 상호작용하는 AI 기능을 넣는다

- 이전 미션의 Python·API 연동 지식을 웹으로 확장 — 입력(폼) → JavaScript `fetch` → Vercel Serverless Function(Python) → AI API → 화면 출력
- AI 가 코드를 써 주더라도 웹이 어떻게 구성되는지 이해하고, 오류의 원인을 직접 파악·수정한다
- 이번 구현 = **AITAG 시연**: 사진 + 프롬프트 매트릭스(분야·콘텐츠 유형·이미지 유형·카테고리·톤) → 대체텍스트 생성 데모

# 2. 과제 목표
> 수료 후 스스로 설명할 수 있다!

# 5. 핵심 개념 정리

## 5-1. HTML · CSS · JS

| | 역할 | 이번 구현에서 |
| --- | --- | --- |
| HTML | 내용과 구조 | 4페이지, 업로드 영역·select 7개·결과 카드 |
| CSS | 표현 | 커스텀 속성 토큰, `[data-theme]` 다크 모드, 860px 반응형 분기 |
| JS | 동작 | 사진 축소(Canvas) · `fetch` · `AbortController` 타임아웃 · DOM 갱신 |

## 5-2. 요청 흐름

```text
select/파일 → JS 가 JSON 조립 → fetch POST /api/alt_text → Python 함수(검증→프롬프트 합성→Gemini) → JSON → render()
```

## 5-3. Vercel Serverless Functions

- `api/파일.py` 하나 = 엔드포인트 하나(`/api/파일`). 요청이 올 때만 실행되고 상태를 갖지 않는다
- `handler` 클래스(`BaseHTTPRequestHandler`)가 진입점 · `_` 로 시작하는 파일은 공유 모듈 · `requirements.txt` 로 패키지 설치
- 로컬(`scripts/dev_server.py`)과 배포에서 같은 `/api/...` 경로 → 프론트 코드는 환경에 따라 바뀌지 않음

## 5-4. 환경 변수와 키 관리

- 키는 서버 함수 안에서만 읽힘(브라우저에 노출되지 않음) · 로컬 `.env`(git 제외) · 배포는 Vercel 환경 변수
- 유출 시 재발급 + 커밋 이력 정리(`git filter-repo`)

## 5-5. 로컬 vs 배포

| | 로컬 | Vercel |
| --- | --- | --- |
| 실행 | `dev_server.py` 한 프로세스 | 정적 CDN + 함수별 컨테이너(콜드 스타트) |
| 키 | `.env` | 환경 변수(Production/Preview 별도) |
| 디버깅 | 터미널 로그 | Deployments → Functions 로그 |
| 수정 반영 | 저장 즉시 | push → 자동 빌드·배포 |

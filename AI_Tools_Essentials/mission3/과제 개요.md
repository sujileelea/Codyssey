# 노코드 자동화 과제 개요

## 1. 미션 소개

이메일 확인 → 스프레드시트 기록 → 팀 채널 공유처럼 한 번에 5분이지만 하루 열 번 반복되면 50분이 사라지는 루틴이 자동화의 출발점이다. Make, Zapier 같은 노코드 자동화 플랫폼은 코딩 없이 Trigger(시작 이벤트)와 Action(처리 동작)을 시각적으로 연결해 반복 업무를 자동화한다.

이번 미션에서는 동일한 워크플로우를 서로 다른 2개 이상의 자동화 도구로 구현·비교 분석한 뒤, 자유 주제로 나만의 자동화 파이프라인을 설계·구현한다.

```text
반복 업무 분석 -> 자동화 가능 여부 판단 -> 도구 선정 -> 워크플로우 구축(Trigger/Action/분기) -> 도구 비교 -> 자유 주제 파이프라인 구현
```

중요한 평가 포인트는 "돌아가기만 하면 된다"가 아니라, Trigger와 Action의 작동 원리를 이해하고 조건 분기를 설계하며 도구별 장단점을 근거 있게 비교하는 것이다. 이 경험은 이후 AI 에이전트 연동, 코드 기반 자동화로 확장하는 발판이 된다.

과제를 마친 후 아래를 스스로 설명할 수 있어야 한다.

- Trigger와 Action의 개념을 설명할 수 있다.
- 조건 분기(Filter/Router)의 역할을 설명할 수 있다.
- 서로 다른 자동화 도구의 특징을 비교할 수 있다.

### 목표별 답변

#### 1) Trigger와 Action의 개념

**Trigger**는 자동화 워크플로우를 시작시키는 사건이다. 이번 과제에서는 Slack `#link-inbox` 채널에 새 메시지가 올라오는 순간을 Trigger로 설정했다. 사용자가 링크를 포함한 메시지를 올리면 별도의 실행 버튼을 누르지 않아도 플로우가 자동으로 시작된다.

**Action**은 Trigger 이후 실제 업무를 처리하는 각 동작이다. 이번 구현의 Action에는 메시지에서 URL 찾기, 중복 링크 기록 조회, jina reader로 원문 가져오기, Gemini로 분류·요약하기, GitHub에 Lea-Loft 글 생성·갱신하기, Slack 스레드에 결과 알리기가 포함된다. 하나의 Trigger 뒤에 여러 Action을 순서대로 연결해 사람이 하던 반복 업무를 끝까지 처리했다.

#### 2) 조건 분기(Filter/Router)의 역할

조건 분기는 앞 단계에서 얻은 데이터를 검사해 실행할 경로를 선택한다. 모든 입력을 같은 방식으로 처리하지 않고 상황별로 다른 Action을 실행하게 만드는 장치다.

이번 프로젝트 1에서는 본문에 오류 경고가 있는지를 검사해 **본문 추출 성공**과 **직접 확인 필요** 경로로 나눴다. Activepieces는 Router로 두 경로를 시각적으로 구성했고, Pipedream은 무료 플랜의 Filter와 조건식을 조합해 통과 또는 종료 흐름을 만들었다.

프로젝트 2에서는 두 번 분기한다. 먼저 URL 기록을 조회해 **신규 링크**는 후속 분석을 계속하고 **중복 링크**는 Slack에 안내한 뒤 플로우를 종료한다. 이후 Gemini가 반환한 AI·기술 뉴스 확신도가 `0.69`보다 높으면 Lea-Loft 발행 경로를 실행하고, 그렇지 않으면 공개 발행 없이 Slack에 분류와 요약만 남긴다. 따라서 중복 게시와 관련성이 낮은 글의 자동 발행을 방지할 수 있다.

#### 3) 서로 다른 자동화 도구의 특징 비교

| 비교 항목 | Activepieces | Pipedream |
|---|---|---|
| 화면 구성 | 노드와 연결선을 사용하는 캔버스형이라 전체 흐름과 분기가 잘 보임 | 세로 단계형이라 단순 흐름을 빠르게 구성하기 좋음 |
| 조건 분기 | 무료 Router에서 여러 경로와 Otherwise를 구성할 수 있음 | 무료 플랜은 Filter의 통과·종료 중심이며 If/Else·Switch는 유료 기능 |
| 데이터 가공 | Text Helper, Code 등 별도 피스를 연결하는 방식 | 입력 필드에서 JavaScript 표현식을 직접 사용할 수 있어 유연함 |
| 실행 로그 | 실행된 경로가 캔버스 위에 표시돼 분기 결과를 확인하기 쉬움 | 이벤트별 단계 결과, Filter EXIT, Replay 기능이 디버깅에 유용함 |
| 무료 운영 | Cloud 무료 크레딧이 있고 Community Edition 셀프호스팅 가능 | 월간 무료 크레딧과 실행 이력·고급 기능 제한이 있음 |
| 적합한 업무 | 다중 분기, 여러 외부 서비스 연결, 시각적 인수인계가 필요한 자동화 | 코드 표현식과 API 데이터 가공이 많은 비교적 단순한 파이프라인 |

두 도구 모두 Slack 링크 수집과 본문 추출 워크플로우를 구현할 수 있었지만, 무료 범위에서 여러 분기를 명확히 구성하고 장기적으로 자체 서버에서 운영하기에는 Activepieces가 더 적합했다. 반면 Pipedream은 JavaScript 표현식과 이벤트 재실행 기능이 강점이었다.

#### 4) 특정 업무에 적합한 도구 선정과 이유

자유 주제인 **Slack 링크 → AI 요약·분류 → Lea-Loft AI News 자동 발행**에는 **Activepieces Community Edition**을 선정했다. 이 업무는 신규·중복 링크 분기, AI 뉴스·비발행 분기, Gemini·GitHub·Slack 연동처럼 여러 경로와 Action이 필요하다. Activepieces는 Router를 무료로 제공하고 실행 경로를 시각적으로 보여 주며, 오픈소스 Community Edition을 Lea-Loft가 운영되는 Mac mini에 셀프호스팅할 수 있다. 따라서 Cloud 실행 크레딧에 계속 의존하지 않고 추가 서비스 비용 없이 운영할 수 있다는 점이 결정적이었다.

#### 5) 자동화 흐름의 단계별 설명

1. **Slack Trigger**: `#link-inbox`에 새 메시지가 올라오면 자동 실행한다.
2. **URL 추출·정규화**: 메시지에서 URL을 찾고 추적 파라미터 등을 정리해 비교 가능한 형태로 만든다.
3. **중복 조회**: Activepieces Tables에서 같은 URL의 처리 기록을 검색한다.
4. **중복 분기**: 신규 링크는 기록을 생성하고 계속 진행한다. 이미 처리한 링크는 Slack 스레드에 중복 안내를 남긴 뒤 Stop Flow로 종료한다.
5. **본문 추출**: `r.jina.ai/{원본 URL}`을 HTTP로 호출해 웹페이지 본문을 마크다운으로 가져온다.
6. **AI 분석**: Gemini 3.5 Flash-Lite가 제목, 분류, 태그, 핵심 요약, 발행용 본문, 원문 인포그래픽 URL, 확신도를 구조화 JSON으로 생성한다.
7. **JSON 변환**: Gemini 응답을 Router와 후속 Action에서 사용할 객체로 변환한다.
8. **AI 뉴스 분기**: 확신도 `> 0.69`이면 발행 경로로 보내고, 그 이하면 Slack에 분류·요약만 전달한다.
9. **발행 파일 준비**: 원문 제목을 기준으로 파일명과 마크다운을 만들고 원본 링크 및 실제 원문 인포그래픽 URL을 포함해 Base64로 변환한다.
10. **GitHub upsert**: 기존 파일의 `sha`를 조회한다. 파일이 있으면 `sha`를 포함해 갱신하고, 없으면 새 파일로 생성해 Lea-Loft 공개 저장소에 반영한다.
11. **결과 알림**: 원래 Slack 메시지의 스레드에 발행 완료 여부, 제목, 핵심 요약, Lea-Loft 링크를 남긴다.

## 4. 기능 요구 사항

### 공통 요구 사항

실제로 동작하는 자동화 워크플로우를 구현해야 한다.

| 구성 요소 | 최소 수량 | 비고 |
|---|---:|---|
| Trigger | 1개 이상 | |
| Action | 2개 이상 | |
| 조건 분기(Filter/Router) | 1개 이상 | 각 분기 경로가 실제로 1회 이상 실행된 결과를 확인할 수 있어야 함 |

### 프로젝트 1 요구 사항

- 서로 다른 2개 이상의 자동화 도구를 사용한다.
- 동일한 워크플로우 구조로 구현한다.
- 비교 분석 보고서에 아래 항목을 포함한다.
  - 사용한 도구 이름
  - 구현 과정 요약
  - 최소 5개 이상의 비교 항목 (예: UI/UX, 설정 난이도, 연동 서비스 범위, 무료 플랜 범위, 실행 로그 확인 방식 등)
  - 각 도구의 장단점 정리
  - 어떤 상황에서 적합한지 의견

### 프로젝트 2 요구 사항

- 자동화할 반복 업무 1개를 정의한다.
- 도구 1개를 선정하고 선정 이유를 작성한다.
- 자동 실행 구조를 구현한다 (Trigger 발생 시 자동 실행).
- 워크플로우 흐름 설명을 포함한다.

## 6. 제약 사항

### 구현 및 동작 제약

- 비교 분석을 위해 도구를 반드시 2개 이상 직접 사용해야 한다.
- 두 프로젝트 모두 "실제 동작하는 워크플로우"여야 한다 (설계 문서만 제출 불가).
- 프로젝트 2는 Trigger 발생 시 자동 실행되어야 한다.

### 보안 및 제출물 제약

- 제출물(스크린샷/문서/공유 링크)에 API Key, 토큰, 비밀번호 등 민감정보가 노출되지 않도록 한다.
- 필요 시 값은 마스킹 처리(예: `***`)하고 계정 이메일도 일부 가림 처리한다.

### 계정/연동 환경 리스크 완화 가이드

권장 최소 구성 예시 (계정 진입장벽이 비교적 낮은 조합):

- Google Sheets + Gmail(또는 Email) + Webhook
- Google Sheets + (Slack 또는 Discord 중 1개) + Webhook

### 과금 리스크 완화 가이드

- 무료 플랜으로 완수 가능한 조합을 우선 고려한다 (예: Make 무료 범위 + Google Sheets, 또는 자가호스팅 가능한 도구 + 무료 연동 앱).
- 유료 결제가 필요한 기능을 사용했다면 "왜 불가피했는지"와 "무료 대안"을 보고서에 함께 정리한다.

## 7. 결과 예시 (참고용 — 정답 아님)

### 프로젝트 1 예시: Make vs Zapier

워크플로우: "Google Form 제출 → 조건 분기(점수 기준) → Google Sheets 기록 + Slack 알림"

| 단계 | Make 구현 | Zapier 구현 |
|---|---|---|
| Trigger | Google Forms – Watch Responses | Google Forms – New Response in Spreadsheet |
| 분기 | Router: 점수 80점 이상 / 미만 | Filter: 점수 80점 이상만 통과 |
| Action 1 | Google Sheets – Add a Row (합격자 시트) | Google Sheets – Create Spreadsheet Row |
| Action 2 | Slack – Send a Message (합격 알림) | Slack – Send Channel Message |

비교 항목 예시 (표로 작성 권장):

| 비교 항목 | Make | Zapier |
|---|---|---|
| UI/UX | 시각적 노드 기반 | 리스트 기반 |
| 설정 난이도 | 초기 학습 곡선 있음 | 직관적 |
| 연동 서비스 범위 | 광범위 (세부 커넥터 차이 존재) | 광범위 (세부 커넥터 차이 존재) |
| 무료 플랜 | 1,000 Ops/월 (예시) | 100 Tasks/월 (예시) |
| 실행 로그 | 실행 히스토리에서 단계별 데이터 확인 | Task History |

### 프로젝트 2 예시: 팀 회의록 자동 정리 및 알림

- 반복 업무 정의: 매주 회의 후 회의록을 Google Docs에 작성하면 핵심 내용을 요약해 Slack 채널에 공유
- 선정 도구: Make (시각적 분기 설계가 직관적이고 무료 Ops 범위 내 구현 가능)
- 워크플로우 흐름:
  1. Trigger: Google Docs – Watch Documents (새 문서 감지)
  2. Action 1: 텍스트 파싱 (제목/참석자/결정사항 추출)
  3. Filter: 결정사항이 존재하는 경우에만 다음 단계로
  4. Action 2: Slack – Send a Message (요약 내용 + 담당자 멘션)
  5. Action 3: Google Sheets – Add a Row (회의록 이력 기록)

### 프로젝트 1

- [ ] 서로 다른 2개 이상의 도구로 동일한 워크플로우 구조를 구현했다.
- [ ] 도구별 구성 화면과 실행 결과 화면을 캡처했다.
- [ ] 보고서에 도구 이름, 구현 과정 요약, 비교 항목 5개 이상, 장단점, 적합 상황 의견이 들어 있다.

### 프로젝트 2

- [ ] 반복 업무 1개 정의와 도구 선정 이유가 작성되어 있다.
- [ ] Trigger 발생 시 자동 실행되는 구조다.
- [ ] 워크플로우 설계 문서(설명 또는 다이어그램)와 구현/실행 캡처가 있다.

### 보너스 (선택 수행 시)

- [ ] AI 연동 Action으로 텍스트를 자동 생성했다.
- [ ] 실패 알림 및 재시도/대체 경로를 설계했다.

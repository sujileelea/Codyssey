# 자동화 도구 비교 구현 보고서 (Activepieces vs Pipedream)

> 초안(2026-08-26). 구현 과정·비교 항목의 실측 값은 구축 후 채운다.

## 1. 사용한 도구

| 항목 | Activepieces | Pipedream |
|---|---|---|
| 형태 | 오픈소스(MIT) · Cloud 무료 플랜 사용, 자가호스팅 가능 | 서버리스 SaaS(Workday 인수) · 무료 플랜 |
| 플랜 | Free (카드 불필요) — 한도 _실측_ | Free — 한도 _실측_ (2차 자료: 월 100 credits·활성 3개) |
| 워크플로우명 | 프로젝트1 링크 본문 추출 (Activepieces) | 프로젝트1 링크 본문 추출 (Pipedream) |

## 2. 공통 워크플로우

**업무**: Slack 채널에 링크를 올리면 링크를 열어 본문을 가져오고, 본문을 읽을 수 있었는지에 따라 스레드에 결과를 달아 준다.

```text
Slack #mission3-demo 새 메시지
  → Filter: 봇 메시지 아님 AND URL 포함
  → Action 1: 본문 추출 (HTTP GET https://r.jina.ai/{url})
  → 조건 분기: 본문 추출 성공? (오류 없음 AND 본문 길이 ≥ 300자)
      ├ 예   → Action 2: 스레드 답글(제목 + 앞부분) + Action 3: 원 메시지에 ✅ 리액션
      └ 아니오 → Action 4: 스레드 답글("본문을 읽을 수 없음 — 직접 확인") + Action 5: ❓ 리액션
```

### 구현 대응표

| 단계 | Activepieces | Pipedream |
|---|---|---|
| Trigger | Slack – New Message (채널 지정, 즉시) | Slack – New Message In Channels (Instant) |
| Filter | Router 앞 Filter 조건 | Filter – Continue if… |
| URL 추출 | Text Helper(정규식) | Formatter / 정규식 |
| 본문 추출 | HTTP – Send Request (GET) | HTTP / Webhook – Send GET Request |
| 분기 | Router (2경로 조건) | Control Flow – If/Else |
| Slack 답글·리액션 | Slack – Send Message(thread) / Add Reaction | Slack – Reply to Thread / Add Reaction |

### 실행 결과 (실측)

_구축 후 기입_: 테스트 링크 2종(일반 문서 링크 = 성공 경로, YouTube 링크 = 실패 경로)으로 두 도구 모두 양쪽 분기가 1회 이상 실행된 결과를 Slack 스레드·실행 로그에서 확인.

## 1. 핵심 개념 (개념 질문 대비)

| 용어 | 정의 키워드 |
|---|---|
| **Trigger** | 워크플로우를 시작시키는 이벤트. 예: Google Sheets 새 행 감지, Gmail 새 메일 |
| **Action** | Trigger 이후 실제로 수행되는 처리 동작. 예: 시트에 행 추가, Slack 메시지 전송 |
| **Filter** | 조건에 안 맞으면 **그 경로를 멈춤**(단일 경로 통과/차단) |
| **Router** (Make) | 하나의 흐름을 **여러 경로로 분기**, 경로마다 필터를 따로 검사 → 3갈래 이상 확장 쉬움 |
| **IF 노드** (n8n) | true/false **두 출력 고정**. 3갈래 이상 필요하면 Switch 노드로 교체 |

**한 줄 정리**: Trigger=시작, Action=처리, Filter=통과여부 판단, Router/IF=경로 나누기

## 2. 프로젝트1 — Make vs n8n (지원서 자동 심사)

### 워크플로우 구조 (동일)
```
Google Form 제출 → 시트 새 행 → Trigger 감지
  → 점수 ≥ 80 분기
      예 → 합격자 시트 기록 + Slack 알림
      아니오 → 불합격 시트 기록
```

### 대응표 키워드
| 단계 | Make | n8n |
|---|---|---|
| Trigger | Watch New Rows | Google Sheets Trigger(rowAdded) |
| 분기 | **Router**+필터 2개 | **IF** 노드(true/false) |
| Slack 발송 | HTTP모듈+Incoming Webhook(**우회**) | Slack 노드(정상) |
| 실행주기(무료) | **15분** | **1분** |

### 비교 항목 8개 (요구사항: 5개 이상 — 8개 준비해서 여유 확보)
1. **분기 표현 방식**: Router(다갈래 유리) vs IF(2갈래 고정)
2. **최소 실행 주기**: 15분 vs 1분
3. **커넥터 안정성**: Make는 Slack·Gmail OAuth **실패**(Resource not found) / n8n은 전부 성공
4. **이식성**: 블루프린트 JSON **파일** export/import vs 노드 JSON **클립보드** 복붙
5. **데이터 매핑 문법**: 컬럼 인덱스 토큰(GUI) vs **JS 표현식**(정규식 등 문자열 가공 강함)
6. **실행 로그**: History 번들 단위 vs Executions **노드별 부분 실행(Execute step)**
7. **에러 처리**: 우클릭 error handler vs **On Error + Retry On Fail** 내장
8. **무료 한도**: 1,000 ops/월 vs 체험 1,000 executions/14일

### 장단점 한 줄
- **Make 장점**: Router 가독성, 블루프린트 백업/이관, 폼 기반이라 표현식 몰라도 OK
- **Make 단점**: Slack/Gmail OAuth 실패 → 우회 필요, 최소주기 15분, 정규식 불편
- **n8n 장점**: 인증 안정적, JS 표현식으로 정규식·날짜변환 자유, 노드 단위 디버깅, 클립보드 이식
- **n8n 단점**: IF 2갈래 고정, 체험판 기간·횟수 제한, 시트 헤더 바뀌면 실패

### 적합 상황
- Make → 비개발 직군, 다갈래 분기, 시각적 인수인계
- n8n → 데이터 가공(파싱/정규식) 필요, 짧은 실행 간격, 장기 비용 고정(자가호스팅)

### "왜 n8n 선택?" 한 줄 답변
> 같은 계정에서 Make는 Slack·Gmail OAuth가 반복 실패했고, n8n은 전부 정상 연결됐다. 금액 정규식 파싱도 n8n JS 표현식이 유리해서 n8n으로 결정.

## 3. 프로젝트2 — 금전 메일 자동 수집·정리 (n8n)

### 반복 업무
금전 관련 메일(결제/입금/청구/영수증)이 여러 계정에 흩어짐 → 사람이 눈으로 금액 옮겨 적음 → **자동화 대상**: 감지 → 금액 추출 → 시트 적재 → 월 누적 합계 Slack 알림

**저장 항목 = 날짜·금액만**(발신처·카드번호 등 미저장) → 보안 리스크 자체 제거

### 흐름 (7단계, mermaid 있음)
```
Gmail Trigger(1분 폴링, 검색어 필터)
 → IF 금액 인식(정규식 [0-9][0-9,]{2,}\s*원)
    true  → 금전_기록 시트 적재 → 전체 조회 → Code노드 이번달 합계 → Slack 알림
    false → 임시_적재 시트(미인식)
 [금전 기록 추가 실패 시] → Slack 실패알림 + 임시_적재 대체저장
```

### 도구 선정 이유 (5가지 키워드)
1. Gmail 커넥터 안정성 (Make는 실패 이력)
2. 정규식 파싱 필요 (JS 표현식)
3. Code 노드로 월 합계 자체 계산 가능
4. 실행주기 1분 (Make 15분보다 즉시성)
5. 자가호스팅 장기 무료 + 금융데이터 외부 SaaS 미노출

### 보너스1 — AI 연동
※ 문서상 명시적 AI Action 언급 없음 → **선택 미수행 여부 확인 필요** (디펜스 전 재확인 권장)

### 보너스2 — 실패 알림 및 재시도 (구현됨)
| 장치 | 설정 |
|---|---|
| 재시도 | Retry On Fail, 최대 2회, 간격 2초 |
| 실패 알림 | On Error → Slack 실패 알림 노드 |
| 대체 경로 | 같은 에러 출력 → 임시_적재 시트에 "저장실패" 표기 |

**핵심 포인트**: 에러 출력을 쓰면 실패 건이 전체 워크플로우를 멈추지 않고 별도 경로로 흘러 뒤 메일 처리가 계속됨.

### 다중 계정 확장 방법
n8n 워크플로우 1개당 트리거 1개 → **계정 수만큼 워크플로우 복제**, Gmail Trigger만 새 자격증명, 나머지 노드(Sheets/Slack)는 자격증명 재사용 → 같은 시트에 모임

### 알려진 한계 (질문 대비)
- 금액 추출 범위: 제목+본문 **snippet만**(본문 하단/첨부 미포함) → 미인식 처리
- 숫자 여러 개면 **첫 번째 매치**만 사용 → 발신처별 정규식 분기하면 정확도 개선
- 취소/환불도 같은 검색어에 걸림 → "총액"이 아니라 "금전 이벤트 합계"에 가까움 (부호 구분은 확장과제)
- 시트 헤더(Date, Amount) 변경 시 스키마 불일치로 실패

### 자동 실행 증빙
Publish(활성화) 상태 유지, 1분 폴링 자동 실행 이력(성공 6건, 에러 2건—개발중 스키마 이슈, 이후 수정) 캡처로 확인

## 4. 예상 질문 & 즉답 키워드

| 질문 | 답변 키워드 |
|---|---|
| Trigger/Action이 뭔가요? | 시작 이벤트 / 처리 동작 |
| Filter와 Router 차이는? | Filter=통과여부만 판단(단일경로), Router=여러 경로로 분기 |
| 조건 분기는 어떻게 구현했나요? | P1: 점수≥80, P2: 정규식으로 금액 패턴 존재 여부 |
| 두 도구 중 뭐가 더 나았나요? | 커넥터 인증 안정성·표현식 자유도에서 n8n 우세 (Make는 OAuth 실패로 Webhook 우회) |
| 왜 Make Slack은 HTTP 모듈로 우회했나요? | Slack/Gmail OAuth가 `Resource not found`로 반복 실패 → Incoming Webhook+HTTP로 대체 |
| 실패하면 어떻게 되나요? | Retry On Fail 2회 → 그래도 실패시 On Error로 Slack 알림 + 임시_적재 대체 저장, 전체 흐름은 안 멈춤 |
| 다른 Gmail 계정도 되나요? | 워크플로우 복제 + Trigger만 새 자격증명, 나머지 자격증명 재사용 |
| 민감정보 처리는? | 저장 항목을 날짜·금액으로 제한, Webhook URL/시트ID 전체 미기재, 이메일·본문 가림 처리 |
| 무료로 다 했나요? | 네. Make Free, n8n 체험판, Slack Webhook 무료. 체험 종료 후엔 n8n 자가호스팅으로 무료 지속 가능 |
| 정규식은 왜 필요했나요? | 메일 본문에서 숫자+"원" 패턴만 추출(`[0-9][0-9,]{2,}\s*원`), 쉼표 제거 후 숫자화 |
| 실행 주기 차이가 왜 생기나요? | 무료 플랜 제약: Make 최소 15분 vs n8n 1분 폴링 |
| Router/IF 노드 확장성은? | Router는 다갈래 자연 확장, IF는 2갈래 고정이라 3갈래부터 Switch 노드 필요 |

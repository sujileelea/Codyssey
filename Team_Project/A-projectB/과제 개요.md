# 뉴스 AI 파이프라인 팀 과제 개요

## 1. 미션 소개

데이터를 수집하고, 정제하고, AI로 분석하고, 리포트로 내보내는 흐름이 데이터 파이프라인이다. 각 단계를 따로 해본 적은 있어도 하나의 서비스로 연결하는 것은 처음일 수 있다. 이번 미션은 뉴스 자동 수집부터 AI 요약·분석, 인사이트 리포트 생성까지를 **CLI 기반 Python 애플리케이션 1개**로 완성한다.

```text
뉴스 수집(API/RSS + 크롤링) -> raw 저장 -> 정제·중복 처리 -> clean 저장 -> AI 요약 -> AI 인사이트 분석 -> 시각화·리포트 -> CSV/Excel 내보내기
```

중요한 평가 포인트는 "돌아가기만 하면 된다"가 아니라, 외부 API에서 데이터를 가져와 오류를 처리하고, raw와 clean을 분리해 저장하는 이유를 이해하며, AI 호출 결과를 저장·집계·시각화해 리포트로 전달하는 전체 흐름을 설명할 수 있는 것이다.

## 2. 팀 역할

| 팀원 | 담당 파트 | 범위 |
|---|---|---|
| **owner(수지)** | 이 외 전부 | CLI 골격·설정·로깅, 뉴스 수집(RSS + 크롤링), 시각화, 리포트, 내보내기, 통합·검증·문서·제출 |
| **혜민** | 데이터 저장/정제 | 영구 저장소(SQLite) 스키마, raw/clean 분리 저장, 정제 규칙, 중복 정책(skip/upsert), `clean` 서브커맨드, 보너스 `list`/`show` |
| **진성** | 요약 | 뉴스 요약 프롬프트·저장, `summarize` 서브커맨드(대상 선택·스킵·재요약), 공용 AI 클라이언트에 요약 호출 추가 |
| **경학** | 인사이트 분석 | 공용 AI 클라이언트(Gemini), 기간·카테고리 조건 종합 분석(배치→종합), 분석 결과 저장·조회, `analyze` 서브커맨드, 보너스 감성 분석 `sentiment` |

모듈 경계, 함수 시그니처, 데이터 모델과 진행 단계는 `수행 플랜.md`가 정본이다. 팀원 3명은 각자 파트의 1차 구현을 이미 냈고, 그 현황과 통합 판단은 `수행 플랜.md` §1에 있다.

## 3. 최종 산출물

다음 기능이 정상 동작하는 CLI 기반 Python 애플리케이션 1개.

| 영역 | 동작 기준 |
|---|---|
| 뉴스 수집 및 저장 | 외부 뉴스 API(또는 RSS)와 크롤링으로 수집하고 raw/clean 분리 저장이 동작한다. 중복 뉴스는 설정에 따라 skip 또는 upsert 처리된다. |
| AI 기반 뉴스 요약 | 저장된 뉴스 본문을 AI API에 전달해 요약문을 생성·저장한다. 사용자가 CLI에서 요약 대상과 옵션을 지정할 수 있다. |
| AI 기반 인사이트 분석 | 일정 기간 또는 카테고리의 뉴스를 종합 분석해 트렌드, 핵심 키워드, 주요 이슈를 도출한다. 분석 결과가 저장되고 조회 가능하다. |
| 시각화 및 리포트 생성 | 카테고리별 뉴스 분포, 일자별 수집 추이를 차트로 시각화한다. 품질 지표와 TOP N 집계가 포함된 리포트를 생성한다. 결과를 CSV, 엑셀 파일로 내보낼 수 있다. |

## 4. 과제 목표

과제를 마친 후 아래를 스스로 설명할 수 있어야 한다.

- API/RSS 방식과 크롤링 방식의 장단점을 비교하여 설명할 수 있다.
- 외부 API에서 데이터를 수집하고, 오류 상황(타임아웃, 응답 실패 등)을 처리하는 방법을 설명할 수 있다.
- raw 데이터와 clean 데이터를 분리 저장해야 하는 이유와 각 단계의 역할을 설명할 수 있다.
- AI API를 호출하여 텍스트를 요약하거나 분석하는 흐름을 설명할 수 있다.
- 수집된 데이터를 집계하고 matplotlib으로 시각화하는 과정을 설명할 수 있다.

### 목표별 답변 초안

> 설계 기준의 초안이다. 구현·실측 후 실제 수치와 사례로 갱신한다.

#### 1) API/RSS 방식과 크롤링 방식의 비교

| 구분 | API/RSS | 크롤링 |
|---|---|---|
| 데이터 형태 | 구조화된 JSON/XML — 제목·링크·발행일·요약이 필드로 제공됨 | HTML — 원하는 요소를 선택자로 직접 추출해야 함 |
| 안정성 | 제공자가 형식을 보장하므로 파싱이 안정적 | 사이트 마크업이 바뀌면 선택자가 깨짐 |
| 제공 범위 | 제공자가 공개하기로 한 필드만(RSS는 보통 본문 전문이 없음) | 화면에 보이는 것은 대부분 수집 가능(본문 전문 포함) |
| 정책·윤리 | 공개 제공 채널이므로 이용 약관 범위에서 자유로움 | robots.txt·이용 약관 준수, 요청 지연과 빈도 제한 필요 |
| 구현 비용 | 낮음(`feedparser` 등으로 몇 줄) | 높음(요청·파싱·예외·지연·재시도) |
| 이번 과제 역할 | 1차 수집 채널 — 목록·메타데이터 확보 | RSS에 없는 본문 전문 보강 + 섹션 페이지 독립 수집 |

결론: 목록과 메타데이터는 RSS로, 본문 전문은 크롤링으로 보강하는 조합이 안정성과 데이터 완결성을 함께 만족한다.

#### 2) 외부 수집과 오류 처리

- 모든 HTTP 요청에 `timeout`(연결·읽기)을 지정하고 `requests.exceptions.Timeout`, `ConnectionError`, `HTTPError`(4xx/5xx)를 구분해 처리한다.
- 실패한 건은 로깅(WARNING/ERROR)한 뒤 스킵하고 다음 건을 계속 처리한다. 한 건의 실패가 전체 수집을 중단시키지 않는다.
- 일시 장애는 상한이 있는 재시도(최대 2회, 지수 백오프)로 복구하고, 상한을 넘으면 실패로 기록한다.
- 수집 결과는 성공/실패 건수로 요약 출력한다.

#### 3) raw와 clean을 분리 저장하는 이유

- **raw**는 수집 시각·소스·수집 방법과 함께 원본을 그대로 보관하는 append-only 기록이다. 정제 규칙이 바뀌거나 버그가 있어도 raw에서 다시 정제할 수 있으므로 재현성과 감사 가능성을 보장한다.
- **clean**은 필수 필드 검증, 텍스트 정규화, 날짜 형식 통일, 결측값 처리, 중복 정책을 거친 분석용 데이터다. 하류 단계(요약·분석·리포트)는 clean만 읽으므로 데이터 계약이 단순해진다.
- 분리하지 않으면 정제 오류가 원본을 덮어써 되돌릴 수 없고, 수집과 정제의 책임이 섞여 문제 원인을 추적하기 어렵다.

#### 4) AI API로 요약·분석하는 흐름

1. clean 저장소에서 대상 뉴스를 선택한다(`--all`, `--id`, `--unsummarized`).
2. 본문을 프롬프트 템플릿에 넣어 AI API에 요청한다(요약은 건별, 분석은 기간·카테고리 묶음).
3. 응답을 파싱해 저장소에 기록한다(요약은 기사 행에, 분석은 별도 테이블에).
4. API 실패는 로깅 후 스킵하고, 이미 요약된 기사는 기본 스킵해 비용을 아낀다.

#### 5) 집계와 matplotlib 시각화

- 저장소에서 SQL 집계(카테고리별 건수, 일자별 수집 건수)를 얻는다.
- matplotlib에 한글 폰트를 지정(macOS `AppleGothic`, Windows `Malgun Gothic`, Linux `NanumGothic`)하고 막대·선 차트를 PNG로 저장한다.
- 리포트는 같은 집계에서 품질 지표와 TOP N을 계산해 텍스트로 출력하고 차트 파일을 링크한다.

## 5. 기능 요구 사항

다음 요구사항을 모두 만족해야 한다.

### CLI 설계

- `argparse` 서브커맨드 기반 CLI.
- 필수 서브커맨드: `fetch`, `clean`, `summarize`, `analyze`, `report`, `export`
- 각 서브커맨드는 필요한 옵션(예: `--limit`, `--category`, `--date`, `--format`)을 지원한다.

### 뉴스 수집

- 다음 두 가지 방법을 **모두** 구현한다.
  - 방법 1: 공개 뉴스 API 또는 RSS 피드 활용
  - 방법 2: 뉴스 사이트 크롤링(BeautifulSoup 또는 Selenium)
- HTTP 요청 시 타임아웃 설정과 오류 처리를 구현한다.
- 수집된 원본 데이터는 수집 시각, 소스 정보, 수집 방법과 함께 raw 저장소에 저장된다.

### 데이터 정제

- 정제 규칙: 필수 필드 검증, 텍스트 정규화, 날짜 형식 통일, 결측값 처리
- 중복 처리 정책(skip/upsert)을 적용한다.
- 정제된 데이터는 clean 저장소에 별도 저장된다.

### AI 요약

- AI API를 호출하여 뉴스 본문을 요약한다.
- 요약 대상 선택 옵션(`--all`, `--id`, `--unsummarized`)을 제공한다.
- API 실패 시 로깅 후 스킵, 이미 요약된 뉴스는 기본 스킵 처리한다.

### AI 인사이트 분석

- 조건별(기간, 카테고리) 뉴스를 종합하여 AI 분석을 요청한다.
- 분석 항목(2개 이상 필수): 주요 트렌드, 핵심 키워드, 공통점/차이점, 시사점
- 분석 결과는 별도 저장하여 리포트에 활용한다.

### 시각화

- matplotlib으로 최소 2종 차트 생성: 카테고리별 뉴스 수, 일자별 수집 추이
- 한글 폰트 적용, PNG 파일로 저장한다.

### 리포트 생성

- 품질 지표 2개 이상, TOP N 집계 1개 이상, AI 인사이트 결과를 포함한다.
- 콘솔 출력 및 파일(TXT/MD) 저장을 지원한다.

### 데이터 내보내기

- 지원 포맷: CSV, JSONL, Excel 중 최소 2개
- 필터링 옵션(`--status summarized`)을 제공한다.

### 설정 및 로깅

- 설정 파일(`config.json`)로 API 키, 뉴스 소스 URL, 중복 정책 등을 관리한다.
- `logging` 모듈로 INFO/WARNING/ERROR 레벨 로그를 기록한다.

### 데이터 저장

- 반드시 영구 저장소(SQLite 또는 JSONL 파일)를 사용한다.
- 메모리(List/Dict)만으로 데이터를 관리하면 안 된다.

### 코드 구조

- 모든 코드를 단일 파일에 작성하면 안 된다.
- 최소 4개 이상의 모듈로 분리한다.

## 6. 보너스 과제

| 보너스 | 내용 | 담당 |
|---|---|---|
| 데이터 조회 CLI | `list`, `show` 서브커맨드로 목록·상세 조회. 조건 필터링(카테고리, 날짜, 키워드)과 페이지네이션 | 혜민 |
| 감성 분석 | AI API로 뉴스 감성(긍정/부정/중립)을 분석하고 시각화 | 경학(분석, 1차 구현 완료) · owner(차트) |
| 정기 실행 스케줄링 안내 | cron 또는 작업 스케줄러를 이용한 정기 수집 방법을 README.md에 문서화 | owner |

## 7. 개발 환경

- Python 3.10 이상
- AI API 호출은 공식 SDK 또는 `requests` 직접 호출

## 8. 제약 사항

### 기능 범위

- 웹 UI는 구현하지 않는다. CLI만으로 모든 기능이 동작해야 한다.
- 뉴스 소스는 단일 소스로 제한해도 무방하다.

### API 사용

- API 키는 코드에 직접 작성하지 않는다.
- 환경변수 또는 설정 파일로 관리한다.

### 크롤링 윤리/정책 및 요청 제한

- 크롤링 대상 사이트의 정책(robots.txt·이용 약관)을 준수한다.
- 요청 간 지연을 두며, 과도한 요청을 금지한다.

## 9. 결과 예시 (참고용 — 정답 아님)

### 뉴스 수집

```text
$ python main.py fetch --source naver --limit 20

[INFO] raw 저장소에 저장 완료
```

```text
$ python main.py summarize --unsummarized --limit 10

[INFO] 요약 대상: 10건
[INFO] [1/10] ID=42 요약 완료 (328자 → 89자)

...
[INFO] 요약 완료: 10건 성공, 0건 실패
```

### 인사이트 분석

```text
$ python main.py analyze --date-from 20XX-01-01 --date-to 20XX-01-10 --category IT

[INFO] AI 분석 요청 중...

- AI 기술의 산업 전반 확산 가속화
- 클라우드 기반 서비스 경쟁 심화

[핵심 키워드]
AI, 클라우드, 반도체, 데이터센터, 자동화

[시사점]
기업들의 AI 투자 확대가 예상되며...
```

## 10. 제출 전 체크리스트

### CLI·구조

- [ ] `argparse` 서브커맨드 `fetch`, `clean`, `summarize`, `analyze`, `report`, `export`가 모두 동작한다.
- [ ] 코드가 4개 이상의 모듈로 분리되어 있다.
- [ ] `config.json`으로 API 키 위치, 뉴스 소스 URL, 중복 정책을 관리하며 키 값은 코드·저장소에 없다.
- [ ] `logging`으로 INFO/WARNING/ERROR 로그가 기록된다.

### 수집·저장·정제

- [ ] RSS(또는 API)와 크롤링 두 방법이 모두 구현되어 있다.
- [ ] HTTP 타임아웃과 오류 처리(타임아웃·응답 실패)가 구현되어 있다.
- [ ] raw 저장소에 수집 시각·소스·수집 방법이 함께 저장된다.
- [ ] 필수 필드 검증, 텍스트 정규화, 날짜 형식 통일, 결측값 처리가 적용된다.
- [ ] 중복 정책 skip/upsert가 설정으로 전환되고 각각 동작이 확인된다.
- [ ] clean 저장소가 raw와 분리되어 있고 영구 저장소(SQLite)를 사용한다.

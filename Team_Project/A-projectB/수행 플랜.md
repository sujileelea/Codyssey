# 뉴스 AI 파이프라인 수행 플랜

`과제 개요.md`의 요구사항을 팀 4명이 병렬로 구현하기 위한 실행 계획이다. 모듈 경계·함수 시그니처·데이터 모델을 먼저 고정하고, 각자 자기 모듈을 채운 뒤 owner가 통합한다. 이 문서는 팀 작업의 정본이며, 결정이 바뀌면 이 문서를 먼저 고친다.

## 1. 목표와 범위

| 구분 | 내용 |
|---|---|
| 필수 | `fetch`·`clean`·`summarize`·`analyze`·`report`·`export` 6개 서브커맨드가 하나의 CLI로 동작 |
| 보너스 | `list`/`show` 조회, 감성 분석 + 차트, cron 정기 수집 README — 필수 통합 검증 통과 후 착수 |
| 비범위 | 웹 UI, 다중 뉴스 소스 확장, 스케줄러 자체 구현(문서화만) |
| 비용 원칙 | AI API 외 전부 무료. AI도 무료 티어 범위에서 운영(팀원 각자 자기 키 사용) |

## 2. 기술 선택

| 항목 | 선택 | 이유 | 대안 |
|---|---|---|---|
| 언어·버전 | Python 3.10+ (`python3 -m venv .venv`) | 과제 요구. 팀원 로컬 버전이 달라도 3.10 문법까지만 사용 | — |
| 방법 1 수집 | RSS (`feedparser`) — 헤럴드경제 섹션별 피드 | 이전 팀 과제(projectB)에서 검증한 소스. 섹션별 피드를 쓰면 **카테고리 필드가 자연스럽게 확보**됨 | 네이버 뉴스 검색 API(클라이언트 ID 발급 필요, 카테고리 없음) |
| 방법 2 수집 | 크롤링 (`requests` + `BeautifulSoup`) — 같은 사이트 섹션 목록 페이지 + 기사 본문 | RSS에 없는 **본문 전문**을 보강하고, 목록 페이지 독립 수집으로 "두 방법 모두 구현" 충족. Selenium은 브라우저 의존이 커서 제외 | Selenium(동적 페이지일 때만) |
| AI API | Gemini 무료 티어, `requests` 직접 호출 | 개인 과제(미션3)에서 무료 티어·구조화 JSON 응답을 실측. 공식 SDK 없이 HTTP 한 함수로 끝나 팀원 환경 차이가 없음 | OpenAI 호환 엔드포인트(`ai.provider` 설정으로 교체 가능하게 설계) |
| 영구 저장소 | SQLite (`sqlite3` 표준 라이브러리) — 단일 파일 `data/news.db` | 기간·카테고리 조회, upsert, 집계 SQL이 필요해 JSONL보다 유리. 의존성 0 | JSONL(조회·집계를 전부 코드로 써야 함) |
| 시각화 | `matplotlib` | 과제 요구 | — |
| Excel | `openpyxl` | pandas 없이 xlsx 쓰기 가능, 의존성 최소 | pandas + openpyxl |
| 설정·비밀 | `config.json`(커밋) + `.env`(비커밋, `python-dotenv`) | 과제 요구인 config.json과 "키는 코드에 쓰지 않는다"를 동시에 만족. config.json에는 **키를 읽을 환경변수 이름만** 둔다 | — |

## 3. 아키텍처

### 디렉터리

```text
A-projectB/
├── 과제 개요.md
├── 수행 플랜.md
└── app/
    ├── main.py                 # argparse 서브커맨드 진입점 — 파싱만 하고 각 모듈의 run_* 호출
    ├── config.py               # config.json + .env 로드, 기본값, 검증
    ├── log.py                  # logging 설정 (콘솔 INFO + 파일 logs/app.log)
    ├── collector/
    │   ├── rss.py              # 방법 1 — RSS 수집
    │   └── crawler.py          # 방법 2 — 목록·본문 크롤링 (지연·robots·타임아웃)
    ├── storage/
    │   ├── db.py               # SQLite 연결·스키마·CRUD·집계
    │   └── cleaner.py          # 정제 규칙 + 중복 정책 → clean 저장
    ├── ai/
    │   ├── client.py           # AI API 호출 공통 (타임아웃·재시도·JSON 파싱)
    │   ├── summarizer.py       # 건별 요약 (+ 감성)
    │   └── analyzer.py         # 기간·카테고리 종합 인사이트 분석
    ├── report/
    │   ├── charts.py           # matplotlib 차트 → PNG
    │   ├── report.py           # 품질 지표·TOP N·인사이트 → 콘솔/TXT/MD
    │   └── exporter.py         # CSV / JSONL / Excel
    ├── config.json             # 소스 URL·중복 정책·AI 모델·경로 (비밀 없음)
    ├── .env.example            # GEMINI_API_KEY=
    ├── requirements.txt
    ├── README.md               # 설치·실행·cron 안내
    ├── data/                   # news.db (gitignore)
    ├── logs/                   # app.log (gitignore)
    └── output/                 # charts/*.png, report.md, exports/* (gitignore)
```

모듈 수는 11개로 "4개 이상" 요구를 넘긴다. 한 서브커맨드 = 한 모듈의 `run_*` 함수가 원칙이다.

### 데이터 흐름

```text
fetch  : RSS/크롤러 -> RawRecord[] -> raw_articles (append-only, 수집 시각·소스·방법 포함)
clean  : raw_articles(미처리) -> 검증·정규화·날짜 통일·결측 처리 -> 중복 정책(skip/upsert) -> articles
summarize : articles(미요약) -> AI 요약(+감성) -> articles.summary / sentiment 갱신
analyze   : articles(기간·카테고리) -> AI 종합 분석 -> analyses (JSON)
report    : articles·analyses 집계 -> charts/*.png + report.md/txt + 콘솔
export    : articles(필터) -> CSV / JSONL / XLSX
```

## 4. 데이터 모델 (SQLite)

|---|---|---|
| `id` | INTEGER PK | |
| `source` | TEXT | 소스 식별자 (config의 `sources[].name`, 예: `herald`) |
| `method` | TEXT | `rss` 또는 `crawl` |
| `url` | TEXT | 원문 URL (정규화 전 원본) |
| `title` | TEXT | |
| `description` | TEXT | RSS 요약문 (없으면 NULL) |

| `category` | TEXT | 피드·섹션에서 얻은 카테고리 원문 |
| `published_raw` | TEXT | 발행 시각 원문 문자열 (형식 통일 전) |
| `fetched_at` | TEXT | 수집 시각 ISO 8601 (KST) |
| `payload` | TEXT | 원본 전체 JSON (재정제용) |

### `articles` — clean 저장소

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `id` | INTEGER PK | |
| `url` | TEXT | 정규화 URL (스킴·호스트 소문자, 추적 파라미터 제거) |
| `url_hash` | TEXT UNIQUE | `sha256(url)` — 중복 키 |
| `title` | TEXT NOT NULL | 공백 정규화 |
| `body` | TEXT NOT NULL | 본문 (없으면 description으로 대체, 둘 다 없으면 정제 탈락) |
| `category` | TEXT NOT NULL | 표준 카테고리명 (config `category_map`으로 통일, 미매핑은 `기타`) |
| `published_at` | TEXT NOT NULL | `YYYY-MM-DD HH:MM:SS` (KST) |

| `summary` | TEXT | AI 요약 (NULL = 미요약) |
| `summary_model` | TEXT | 사용 모델명 |
| `summarized_at` | TEXT | |
| `sentiment` | TEXT | `positive` / `negative` / `neutral` (보너스) |

## 5. 인터페이스 계약

병렬 작업의 핵심이다. **시그니처를 바꿔야 하면 먼저 팀 채널에 알리고 이 문서를 고친 뒤 코드를 고친다.** 모든 함수는 `dict`/`list[dict]`를 주고받고, 컬럼명은 §4와 동일하다.

### CLI (`main.py`, owner)

| 서브커맨드 | 옵션 | 호출 |
|---|---|---|
| `fetch` | `--source {rss,crawl,all}` (기본 all) · `--limit N` · `--category C` · `--with-body/--no-body` | `collector.rss.run_fetch` / `collector.crawler.run_fetch` |
| `clean` | `--policy {skip,upsert}` (기본 config) · `--limit N` | `storage.cleaner.run_clean` |
| `summarize` | `--all` \| `--id ID [ID ...]` \| `--unsummarized` (기본) · `--limit N` · `--force` · `--max-chars N` · `--with-sentiment` | `ai.summarizer.run_summarize` |
| `analyze` | `--date-from D` · `--date-to D` · `--category C` · `--items trends,keywords,...` (기본 전부) · `--show ID` | `ai.analyzer.run_analyze` / `show_analysis` |
| `report` | `--date-from D` · `--date-to D` · `--category C` · `--top N` (기본 5) · `--format {md,txt}` · `--out PATH` · `--no-charts` | `report.report.run_report` |
| `export` | `--format {csv,jsonl,xlsx}` · `--status {all,clean,summarized}` · `--category C` · `--date-from/--date-to` · `--out PATH` | `report.exporter.run_export` |
| `list` (보너스) | `--category C` · `--date-from/--date-to` · `--keyword K` · `--status` · `--page N` · `--page-size N` | `storage.db.list_articles` |
| `show` (보너스) | `ID` | `storage.db.get_article` |

모든 서브커맨드는 종료 코드 0(성공)·1(부분 실패)·2(설정·인자 오류)를 반환한다. 공통 옵션 `--config PATH`, `--verbose`.

## 6. 역할 분배와 완료 기준

| 담당 | 산출 모듈 | 서브커맨드 | 완료 기준(Definition of Done) |
|---|---|---|---|
| **owner** | `main.py` · `config.py` · `log.py` · `collector/*` · `report/*` · `README.md` · `requirements.txt` | `fetch`, `report`, `export` | 골격이 Phase 0에 먼저 올라가 팀원이 자기 모듈만 채우면 되는 상태. RSS·크롤링 각각 실측 20건 이상 raw 저장. 차트 2종 한글 깨짐 없음. 리포트에 지표 2·TOP N 1·인사이트 포함. CSV·XLSX 생성 |
| **혜민** | `storage/db.py` · `storage/cleaner.py` | `clean`, `list`, `show` | 스키마 자동 생성. 필수 필드·정규화·날짜 통일·결측 처리 각각 테스트 케이스 1개 이상. skip/upsert 정책 전환 실측. 같은 raw를 두 번 clean해도 결과 동일(멱등) |
| **진성** | `ai/client.py` · `ai/summarizer.py` | `summarize` | 클라이언트가 타임아웃·재시도·JSON 파싱 실패를 `AIError`로 통일. `--all/--id/--unsummarized` 동작. 실패 건 로깅 후 스킵, 기요약 건 기본 스킵·`--force` 재요약. 보너스 감성 값이 3종 중 하나로만 저장 |
| **경학** | `ai/analyzer.py` | `analyze` | 기간·카테고리 필터로 대상 선택. 항목 4종 JSON 응답 파싱·저장·`--show` 조회. 콘솔 출력이 과제 예시 형식. 기사 0건일 때 안내 후 종료(AI 호출 없음) |

각자 자기 모듈의 **단독 실행 스크립트 또는 테스트**(`tests/test_<module>.py`, `unittest`)를 함께 낸다. 통합 검증은 owner가 한다.

## 7. 진행 단계

기한은 팀 일정 확정 후 채운다. 단계는 순서만 고정한다.

### Phase 0에서 owner가 먼저 고정하는 것

1. 뉴스 소스 URL 실측 — RSS 피드 파싱 성공, 목록·본문 선택자 확인, `robots.txt` 허용 확인.
2. AI 무료 티어 호출 1회 성공(모델명·응답 형식) — `ai/client.py` 최소 구현을 owner가 먼저 넣고 진성이 인계받아 완성.
3. `db.py` 스키마 DDL — 혜민이 인계받아 CRUD를 채운다.

## 8. 협업 규칙

### Git

- 팀 공용 저장소 1개. 브랜치: `main`(제출본) ← `develop`(통합) ← `feat/<파트>`(`feat/storage`, `feat/summarize`, `feat/analyze`, `feat/collector`, `feat/report`).
- 작업은 `feat/*`에서 하고 `develop`으로 PR. owner가 리뷰·머지한다. `main`은 제출 시점에만 owner가 올린다.
- 커밋은 논리 단위 최소 커밋. 메시지는 `<파트>: <무엇을>` (예: `storage: upsert 정책 구현`).
- `data/`, `logs/`, `output/`, `.env`, `.venv/`는 커밋하지 않는다(`.gitignore`). 공유용 샘플 DB는 `data/sample.db`만 예외로 허용할지 Phase 0에서 결정.

### 비밀·설정

- API 키는 각자 자기 `.env`에만 둔다. `config.json`에는 환경변수 **이름**만 있다.
- 캡처·로그·문서에 키·토큰이 보이면 마스킹한다. `logs/app.log`에 요청 헤더를 남기지 않는다.

### 코드 규칙

- Python 3.10 문법까지. 타입 힌트와 모듈 docstring 필수. 함수 하나가 한 가지 일만.
- 출력은 CLI 결과만 `print`, 진행·오류는 전부 `logging`. 레벨: 정상 진행 INFO, 건별 실패·스킵 WARNING, 단계 중단 ERROR.
- 외부 요청은 반드시 `timeout` 지정. 재시도 상한 2회. 크롤링 요청 간 `delay_seconds` 이상 대기.
- 저장소 접근은 `storage/db.py` 함수만 쓴다. 다른 모듈에서 SQL을 직접 쓰지 않는다.
- AI 호출은 `ai/client.py`만 쓴다. 프롬프트는 각 모듈 상단 상수로 두어 리뷰가 쉽게.

### 소통

- 계약(§4·§5) 변경은 채널 공지 → 이 문서 수정 → 코드 순.
- 막히면 30분 안에 채널에 올린다. 통합 이슈는 owner가 모아 Phase 2에 처리.

## 9. 검증 계획

| 검증 | 방법 | 담당 |
|---|---|---|
| 수집 오류 처리 | 잘못된 URL·`timeout=0.001`로 강제 실패 → WARNING 로그 후 다음 건 진행 확인 | owner |
| raw/clean 분리 | raw 행 수 ≥ clean 행 수, raw는 재실행마다 증가·clean은 정책대로 | 혜민 |
| 중복 정책 | 같은 raw를 `--policy skip`과 `--policy upsert`로 각각 clean → skipped/updated 카운트 비교 | 혜민 |
| 요약 스킵 규칙 | 기요약 건 재실행 시 skipped, `--force` 시 재요약. 키 제거 후 실행 → failed 로깅·종료 코드 1 | 진성 |
| 분석 저장·조회 | `analyze` 후 `analyze --show ID`가 동일 결과 출력. 기사 0건 조건은 AI 미호출 | 경학 |
| 차트 한글 | PNG 열어 축·범례 한글 확인(macOS·Windows 각 1명) | owner |
| 리포트·내보내기 | 지표 2·TOP N 1·인사이트 포함. CSV·XLSX 행 수 = `list` 결과 수. `--status summarized` 필터 일치 | owner |
| 보너스 | `list --page 2`, `show ID`, 감성 차트, cron 항목 README | 각 담당 |

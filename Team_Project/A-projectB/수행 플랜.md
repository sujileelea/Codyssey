# 뉴스 AI 파이프라인 수행 플랜

`과제 개요.md`의 요구사항을 팀 4명이 병렬로 구현하기 위한 실행 계획이다. 팀원 3명은 이미 각자 파트의 1차 구현을 냈으므로(§1), 이 플랜은 **그 작업물을 하나의 CLI로 통합**하는 것을 중심에 둔다. 모듈 경계·함수 시그니처·데이터 모델은 팀원 작업물에 이미 있는 이름을 기준으로 고정하고, 어긋나는 부분만 최소로 맞춘다. 이 문서는 팀 작업의 정본이며, 결정이 바뀌면 이 문서를 먼저 고친다.

## 1. 팀원 작업물 현황 (2026-09-09 검토)

| 담당 | 작업물 | 완성도 | 그대로 쓰는 것 | 통합 시 바꿔야 하는 것 |
|---|---|---|---|---|
| **혜민** 저장/정제 | `hyemin_news_storage/` — `storage.py`(raw_news·news 테이블, skip/upsert) · `cleaner.py`(HTML 제거·공백 정규화·날짜 통일·필수 필드 검증) · `clean_service.py`(전건 정제·건수 로그) · `main.py clean --duplicate-policy` · `config.json` | 필수 요구 충족. 표준 라이브러리만 사용 | 테이블 `raw_news`/`news`, 컬럼 `content`·`collected_at`·`collection_method`, 반환값 `inserted/updated/skipped`, 정책 이름 skip/upsert | ① DB 경로가 `news.db` 하드코딩 → config `database.path` 사용 ② `normalize_date`가 RSS 날짜(RFC 2822)와 시각을 못 받음 → 형식 추가, 출력 `YYYY-MM-DD HH:MM:SS` ③ URL 정규화 없이 UNIQUE → 추적 파라미터 제거 후 비교 ④ 매 실행 raw 전건 재정제 → `raw_news.processed` 플래그 ⑤ 조회·집계 함수 없음 → `list`/`show`/리포트용 집계 추가 ⑥ `create_tables`의 `print` → logging |
| **진성** 요약 | `ai-news-summary/` — `main.py summarize --all/--id/--unsummarized/--limit` · `src/summarizer.py`(OpenAI `gpt-5-mini`, Responses API) · `src/database.py`(news 조회·summary 저장) | CLI·DB 흐름은 동작 확인. **AI 호출은 OpenAI 크레딧 0으로 429 실패, 요약 결과 미확인** | 요약 대상 옵션 3종, 건별 실패 시 계속 진행, 성공/실패 집계, 진행 로그 형식(`[i/n] ID=… 요약 완료 (n자 → m자)`) | ① OpenAI → **Gemini 무료 티어**로 전환(경학 `ai_client.py` 공용) ② import 시점 API 키 검사 → 호출 시점으로(키 없어도 `fetch`·`clean`은 돌아야 함) ③ `print` → logging ④ `--all`이 `--unsummarized`와 동일 → `--all`은 전건 대상·기요약은 기본 스킵·`--force`로 재요약 ⑤ `src/database.py`의 조회 3종은 혜민 `storage.py`로 이관 |
| **경학** 인사이트 | `ai_news_insight_mvp/` — `main.py analyze/sentiment` · `ai_client.py`(Gemini `google-genai` SDK, JSON Schema 응답, Mock 클라이언트) · `insight_analyzer.py`(20건 배치 → reduce, trends 3·keywords 6·major_issues 4) · `sentiment_analyzer.py`(보너스 감성, `sentiment_results` 테이블) · `database.py`(`NewsRepository`, 컬럼 매핑 config) · `models.py` · `tests/` | 필수 + 보너스 감성까지 구현, pytest 있음. 가장 완성도 높음 | `ai_client.py` 전체(팀 공용 AI 클라이언트로 승격), `insights`·`sentiment_results` 테이블, 콘솔 출력 형식, config 구조(`database`·`ai`·`analysis`·`sentiment`·`logging`) | ① `AIClient`에 요약용 `generate_text` 추가(진성이 사용) ② `database.py` 파일명이 충돌 → `repository.py`로 개명 ③ `quantitative_result.daily_counts`가 발행일 기준 → 리포트의 "일자별 수집 추이"는 `collected_at` 기준이므로 owner가 storage 집계를 따로 씀 ④ 분석 항목에 `implications`(시사점) 선택 추가는 여유 시 |

### 통합 판단

- **AI 제공자 = Gemini 무료 티어, SDK `google-genai`, 모델 `gemini-2.5-flash-lite`**. 근거: 경학이 실측 완료, 진성의 OpenAI는 크레딧 부족으로 실패. 팀원 각자 Google AI Studio에서 무료 키를 발급해 자기 `.env`에 둔다. 무료 티어는 분당·일일 요청 한도가 있으므로 `--limit`으로 소량씩 실행한다.
- **DB 스키마 = 혜민 `raw_news`/`news` + 경학 `insights`/`sentiment_results`**. 세 작업물 모두 `news(id, title, content, summary, category, source, published_at)`을 이미 공유하고 있어 컬럼명 충돌이 없다.
- **config.json = 경학 구조를 골격으로 혜민 항목 병합 + owner의 `sources`·`http`·`report` 추가**.
- **감성 분석 보너스는 경학 담당**(이미 구현). 진성은 요약 전환·`--force`·로깅에 집중한다.
- 세 사람의 `main.py`는 하나로 합친다. 각 파트는 `run_*` 함수만 노출하고 argparse 정의는 owner의 `main.py`가 소유한다.

### 데이터 흐름

```text
fetch     : RSS/크롤러 -> raw dict[] -> raw_news (append-only: collected_at·source·collection_method·raw_data)
clean     : raw_news(processed=0) -> 검증·정규화·날짜 통일·결측 처리 -> 중복 정책(skip/upsert, URL 기준) -> news
summarize : news(summary IS NULL) -> Gemini 요약 -> news.summary / summary_model / summarized_at
analyze   : news(기간·카테고리) -> 20건 배치 -> reduce -> insights (JSON 3종)
sentiment : news(content) -> Gemini 감성 -> sentiment_results (news_id UNIQUE, upsert)
report    : news·insights·sentiment_results 집계 -> charts/*.png + report.md/txt + 콘솔
export    : news(필터) -> CSV / JSONL / XLSX
```

## 5. 데이터 모델 (SQLite, `data/news.db`)

### `raw_news` — raw 저장소 (혜민, append-only)

| 컬럼 | 설명 |
|---|---|
| `id` | PK |
| `title` · `url` · `content` · `published_at` | 원문 그대로 (정규화 전) |
| `source` | 소스 식별자 (config `sources[].name`, 예: `herald`) |
| `category` | 피드·섹션에서 얻은 카테고리 원문 |
| `collection_method` | `rss` 또는 `crawl` |
| `collected_at` | 수집 시각 `YYYY-MM-DD HH:MM:SS` (KST) |
| `raw_data` | 원본 전체 JSON |
| `processed` | **추가** — clean 처리 여부 0/1 (기본 0) |
| `created_at` | |

### `news` — clean 저장소 (혜민)

| 컬럼 | 설명 |
|---|---|
| `id` | PK — 요약·분석·감성이 모두 이 id를 참조 |
| `raw_id` | `raw_news.id` |
| `title` NOT NULL | 공백 정규화 |
| `url` UNIQUE | **정규화 URL**(스킴·호스트 소문자, `utm_*` 등 추적 파라미터 제거) — 중복 키 |
| `content` NOT NULL | 본문. 크롤링 본문이 없으면 RSS description으로 대체, 둘 다 없으면 정제 탈락 |
| `summary` | AI 요약 (NULL = 미요약) |
| `summary_model` · `summarized_at` | **추가** — 리포트 품질 지표용 |
| `category` DEFAULT '기타' | config `category_map`으로 표준화 |
| `source` DEFAULT 'unknown' | |
| `published_at` | `YYYY-MM-DD HH:MM:SS` (KST). **현재 `YYYY-MM-DD`만 출력 → 시각까지 확장** |
| `collected_at` | raw에서 승계 — "일자별 수집 추이" 기준 |
| `created_at` · `updated_at` | |

`status`는 컬럼이 아니라 파생값: `summary IS NULL` → `clean`, 아니면 `summarized`. `export --status summarized`와 `summarize --unsummarized`가 이 조건을 쓴다.

### `insights` (경학, 그대로)

`id, date_from, date_to, category, article_limit, sort_order, selected_article_count, summarized_article_count, quantitative_result_json, batch_result_json, insight_result_json, created_at`

`insight_result_json` = `{"trends": [3], "keywords": [6], "major_issues": [4]}` — 리포트의 AI 인사이트 섹션이 이 값을 쓴다.

### `sentiment_results` (경학, 그대로)

`id, news_id UNIQUE, sentiment_result_json, created_at, updated_at` — `{"sentiment": "positive|neutral|negative", "score": -1.0~1.0, "reason": "..."}`

## 6. 인터페이스 계약

병렬 작업의 핵심이다. **시그니처를 바꿔야 하면 먼저 팀 채널에 알리고 이 문서를 고친 뒤 코드를 고친다.** 이미 있는 함수는 이름을 유지하고, 없는 것만 추가한다.

### CLI (`main.py`, owner)

| 서브커맨드 | 옵션 | 호출 | 출처 |
|---|---|---|---|
| `fetch` | `--source {rss,crawl,all}`(기본 all) · `--limit N` · `--category C` · `--no-body` | `collector.rss.run_fetch` / `collector.crawler.run_fetch` | 신규 |
| `clean` | `--duplicate-policy {skip,upsert}`(기본 config) · `--limit N` | `clean_service.clean_saved_articles` | 혜민 |
| `summarize` | `--all` \| `--id ID` \| `--unsummarized`(기본) · `--limit N` · `--force` | `summarizer.run_summarize` | 진성 |
| `analyze` | `--date-from` · `--date-to` · `--category` · `--limit` · `--sort {latest,oldest}` · `--show ID` | `insight_analyzer.InsightAnalyzer.analyze` / `repository.get_insight` | 경학 |
| `sentiment` (보너스) | `--id` \| `--all` \| `--unsentimented`(기본) · 기간·카테고리·`--limit`·`--sort` | `sentiment_analyzer.SentimentAnalyzer.analyze` | 경학 |
| `report` | `--date-from` · `--date-to` · `--category` · `--top N`(기본 5) · `--format {md,txt}` · `--out PATH` · `--no-charts` | `report.report.run_report` | 신규 |
| `export` | `--format {csv,jsonl,xlsx}` · `--status {all,clean,summarized}` · `--category` · `--date-from/--date-to` · `--out PATH` | `report.exporter.run_export` | 신규 |
| `list` (보너스) | `--category` · `--date-from/--date-to` · `--keyword` · `--status` · `--page N` · `--page-size N` | `storage.list_news` | 혜민 신규 |
| `show` (보너스) | `ID` | `storage.get_news` | 혜민 신규 |

공통 옵션 `--config PATH`(기본 `config.json`), `--verbose`. 종료 코드 0(성공)·1(부분 실패)·2(설정·인자 오류). 날짜 인자 검증은 경학 `valid_date`를 공용으로 쓴다.

### 수집 (`collector/`, owner)

```python
# raw dict 키 = raw_news 컬럼: title, url, content, published_at, source, category, collection_method, collected_at (+ raw_data는 storage가 만든다)
fetch_rss(source: dict, limit: int, http: dict) -> list[dict]
```

## 9. 협업 규칙

### Git

- 팀 공용 저장소 1개. 브랜치: `main`(제출본) ← `develop`(통합) ← `feat/<파트>`(`feat/storage`, `feat/summarize`, `feat/analyze`, `feat/collector`, `feat/report`).
- 작업은 `feat/*`에서 하고 `develop`으로 PR. owner가 리뷰·머지한다. `main`은 제출 시점에만 owner가 올린다.
- 커밋은 논리 단위 최소 커밋. 메시지는 `<파트>: <무엇을>` (예: `storage: URL 정규화 추가`).
- `data/`, `logs/`, `output/`, `.env`, `.venv/`, `config.json`은 커밋하지 않는다(`config.example.json`만 커밋). 공유용 `data/sample.db`는 Phase 0에서 예외 여부 결정.

### 비밀·설정

- API 키는 각자 자기 `.env`에만 둔다. `config.json`에는 환경변수 **이름**만 있다.
- 캡처·로그·문서에 키·토큰이 보이면 마스킹한다. `logs/app.log`에 요청 헤더를 남기지 않는다.

### 코드 규칙

- Python 3.10 문법까지. 타입 힌트와 모듈 docstring. 함수 하나가 한 가지 일만.
- 출력은 CLI 결과만 `print`, 진행·오류는 전부 `logging`. 레벨: 정상 진행 INFO, 건별 실패·스킵 WARNING, 단계 중단 ERROR. 로그 형식 `[%(levelname)s] %(message)s`(세 작업물 공통).
- 외부 요청은 반드시 `timeout` 지정. 재시도 상한 2회. 크롤링 요청 간 `delay_seconds` 이상 대기.
- `news`·`raw_news` **쓰기**는 `storage.py`만 한다. 분석·감성의 읽기 전용 조회와 자기 테이블(`insights`·`sentiment_results`)은 `repository.py`가 맡는다.
- AI 호출은 `ai_client.py`만 쓴다. 프롬프트는 각 모듈 상단 상수.

### 소통

- 계약(§5·§6) 변경은 채널 공지 → 이 문서 수정 → 코드 순.
- 막히면 30분 안에 채널에 올린다. 통합 이슈는 owner가 모아 Phase 2에 처리.

# 뉴스 AI 파이프라인 수행 플랜

`과제 개요.md`의 요구사항을 하나의 완성된 CLI로 만들기 위한 실행 계획이다. 혜민(저장/정제)·진성(요약)·경학(인사이트)은 각자 파트의 1차 구현을 냈고, **owner의 일은 이 세 작업물을 수합해 하나의 완성된 과제로 다듬는 것**이다. 따라서 이 플랜은 ① 세 작업물이 이미 정해 놓은 것, ② 서로 어긋나 owner가 정리해야 하는 것, ③ 아무도 정하지 않아 owner가 새로 정해야 하는 것을 구분하는 데서 출발한다. 이 문서는 팀 작업의 정본이며, 결정이 바뀌면 이 문서를 먼저 고친다.

## 1. 팀원 작업물 현황 (2026-09-09 검토)

| 담당 | 작업물 | 완성도 | 이미 정해 놓은 것 |
|---|---|---|---|
| **혜민** 저장/정제 | `hyemin_news_storage/` — `storage.py`(`raw_news`·`news` DDL, `save_raw_article`, `save_clean_article` skip/upsert) · `cleaner.py`(HTML 제거·공백 정규화·날짜 통일·필수 필드 검증) · `clean_service.py`(raw 전건 정제·건수 로그) · `main.py clean --duplicate-policy` · `config.json` · `config_loader.py` | 필수 요구 충족. 표준 라이브러리만 사용 | 테이블 `raw_news`/`news`와 컬럼 전체, raw 필드명(`content`·`collection_method`·`collected_at`·`raw_data`), 중복 키 = `url` UNIQUE, 반환값 `inserted/updated/skipped`, 정책 이름 skip/upsert, 필수 필드 = 제목·URL·본문, 카테고리 기본값 `기타`·소스 기본값 `unknown`, 로그 파일 `logs/app.log` |
| **진성** 요약 | `ai-news-summary/` — `main.py summarize --all/--id/--unsummarized/--limit` · `src/summarizer.py`(OpenAI `gpt-5-mini`, Responses API) · `src/database.py`(`news` 조회·`summary` 저장) | CLI·DB 흐름 동작. **AI 호출은 OpenAI 크레딧 0으로 429 실패, 요약 결과 미확인** | 요약 결과는 `news.summary` 컬럼, 미요약 = `summary IS NULL`, 요약 조건(3~5문장·객관·원문 외 내용 금지), 건별 실패 시 계속 진행, 진행 로그 형식 `[i/n] ID=… 요약 완료 (n자 → m자)` |
| **경학** 인사이트 | `ai_news_insight_mvp/` — `main.py analyze/sentiment` · `ai_client.py`(Gemini `google-genai` SDK, JSON Schema 응답, `MockAIClient`) · `insight_analyzer.py`(20건 배치 → reduce) · `sentiment_analyzer.py`(보너스) · `database.py`(`NewsRepository`, 테이블·컬럼명 config 매핑) · `config.py` · `models.py` · `tests/`(pytest) | 필수 + 보너스 감성까지 구현, 테스트 있음. 가장 완성도 높음 | `insights`·`sentiment_results` 테이블과 JSON 형식, 분석 항목 = trends 3·keywords 6·major_issues 4, 감성 = positive/neutral/negative + score + reason, 정성 분석은 `summary` 있는 기사만(0건이면 오류), 재시도 상한 config, 콘솔 출력 형식, config 구조(`database`·`ai`·`analysis`·`sentiment`·`logging`), 날짜 인자 검증 `valid_date` |

세 작업물이 공통으로 전제하는 것: SQLite 단일 파일, `news(id, title, content, summary, category, source, published_at)` 컬럼명, `[%(levelname)s] %(message)s` 로그 형식(진성은 print로 흉내). 이 공통분모는 그대로 팀 표준으로 삼는다.

## 2. owner가 새로 결정해야 하는 항목

### A. 세 작업물이 서로 어긋나는 것 (통합하려면 하나로 정해야 함)

| # | 항목 | 현재 상태 (근거) | 선택지 | 권고 |
|---|---|---|---|---|
| A1 | DB 파일 경로 | 혜민 `news.db` 상수 · 진성 `news.db` 상수 · 경학 config `data/news.db` | 상수 통일 / config 단일값 | config `database.path` 하나로. 혜민·진성 상수 제거 |
| A2 | `published_at` 형식 | 혜민 `normalize_date`는 `YYYY-MM-DD`만 출력(시각 버림, RSS 표준 날짜 형식 미지원) · 경학은 `YYYY-MM-DD HH:MM:SS`로 정렬·테스트 | 날짜만 / 날짜+시각 | `YYYY-MM-DD HH:MM:SS`(KST). 혜민 함수에 RFC 2822·ISO 입력 추가 |
| A3 | `config.json` 구조 | 혜민 `{database.path, cleaning.duplicate_policy, logging.level/file}` · 경학 `{database.*, ai, analysis, sentiment, logging.level}` · 진성 `.env`만 | 둘 중 하나 채택 / 병합 | 경학 구조에 혜민 `cleaning`·`logging.file` 병합 + owner `sources`·`http`·`summary`·`report` 추가. 키 값은 `.env`, config에는 환경변수 이름만(경학 방식) |
| A4 | 로깅 설정 | 혜민 `clean_service` import 시 `basicConfig`(콘솔+파일) · 경학 `main`에서 `basicConfig`(콘솔) · 진성 `print` | — | 단일 `log.py`에서 1회 설정. 모듈 단에서 `basicConfig` 호출 제거, 진성 print → logging |
| A5 | AI 클라이언트 | 경학 Gemini SDK(JSON Schema 응답, insight·sentiment 전용 메서드) · 진성 OpenAI SDK(자유 텍스트) | 두 SDK 병행 / 하나로 | **owner 결정 완료: 전 파트 무료 모델만**. 경학 `ai_client.py`를 공용으로 쓰고 요약용 `generate_text` 추가. 진성 OpenAI 제거. 남은 결정 = 한도 소진 시 대체 무료 경로 지정 여부 |
| A6 | `news` DDL 소유 | 혜민 `create_tables`(전체 컬럼) · 진성 `create_table`(4컬럼 — 같은 이름 다른 정의) · 경학은 존재 전제 | — | 혜민 DDL만 남긴다. 진성 DDL·테스트 삽입 스크립트는 삭제 또는 `tests/`로 |
| A7 | 파일명 충돌 | 경학 `database.py`·`config.py` vs 진성 `src/database.py` vs 혜민 `storage.py`·`config_loader.py` | 패키지로 분리 / 개명 | 평면 구조 유지, 경학 `database.py`→`repository.py`, 진성 `src/database.py`는 혜민 `storage.py`로 흡수, config는 하나 |
| A8 | `summarize --all` 의미 | 진성은 `--all`과 `--unsummarized`가 동일(미요약 전건). 과제는 둘을 구분하고 "기요약은 기본 스킵" | 현행 유지 / 구분 | `--all` = 전건 대상(기요약 스킵), `--unsummarized` = 미요약만(기본), `--force` = 재요약 |
| A9 | upsert 시 요약 보존 | 혜민 upsert는 `summary = NULL`로 초기화 → 재정제하면 진성이 저장한 요약이 사라짐 | 초기화 유지 / 보존 / 본문 변경 시만 초기화 | 본문이 실제로 바뀐 경우만 초기화, 아니면 보존 |
| A10 | 재정제 범위 | 혜민 `clean_service`는 매 실행 raw 전건 재처리(처리 플래그 없음). skip이면 멱등이나 건수가 커지면 느리고, upsert면 A9 문제 | 전건 유지 / 미처리분만 | `raw_news.processed` 플래그 추가, 기본은 미처리분만, `--all`로 전건 |
| A11 | 분석 전제 | 경학 `analyze`는 summary 없는 기사 제외, summary 0건이면 오류 → `summarize` 선행 필수 | 유지 / summary 없으면 content 폴백 | 유지(요약이 곧 정성 분석 입력). README에 실행 순서 명시 |
| A12 | 분석 항목 | 경학 trends·keywords·major_issues. 과제 4항목(트렌드·키워드·공통점/차이점·시사점) 중 2개 충족 | 유지 / 시사점 추가 | 유지. 여유 시 `implications` 추가 |
| A13 | 카테고리 값 체계 | 혜민 기본 `기타` · 경학 필터는 **정확 일치**(테스트 값 `AI`·`반도체`) · 실제 값은 수집 소스가 결정 | — | B2로 확정: BBC 코리아 섹션명 5종을 그대로 표준명으로 쓴다. RSS 건은 섹션 정보가 없으므로 정제 단계에서 같은 URL의 크롤링 raw 행에서 카테고리를 찾아 채우고, 없으면 `기타` |
| A14 | 감성 결과 위치·시각화 | 경학 별도 테이블 `sentiment_results`(news_id UNIQUE). 시각화는 미구현 | 유지 | 유지. 차트는 owner `report` 파트 |

### B. 아무도 정하지 않은 것 (owner 파트 설계)

| # | 항목 | 왜 필요한가 | 결정할 내용 |
|---|---|---|---|
| B1 | **뉴스 소스** | 세 작업물 모두 수집을 다루지 않는다. 테스트 데이터는 손으로 넣은 예시뿐 | **owner 결정 완료(2026-09-09): BBC 코리아 단일 소스.** 방법 1 = RSS `https://feeds.bbci.co.uk/korean/rss.xml`, 방법 2 = 섹션(topic) 페이지 목록 크롤링 + 기사 본문 크롤링. 실측 근거는 §2-1 |
| B2 | 카테고리 표준 명칭 | A13 | **결정 완료**: BBC 코리아 섹션명 그대로 `국내`·`세계`·`북한`·`건강·과학`·`문화` 5종 + `기타`. `비디오` 섹션은 본문이 없어 제외. `category_map`은 항등 매핑(섹션명 변경 대비용) |
| B3 | raw 필드 계약 | 혜민 `raw_news` 컬럼이 곧 계약 | owner `fetch`가 만드는 dict 키 = `title, url, content, published_at, source, category, collection_method, collected_at`. 새 결정은 없고 준수만 |
| B4 | HTTP 정책 | 과제 요구(타임아웃·오류 처리·지연) | timeout·재시도 횟수·요청 간 지연·User-Agent 값 |
| B5 | 리포트 정의 | 과제 요구(품질 지표 2+, TOP N 1+, 인사이트 포함) | 품질 지표 후보: 요약 완료율, 필수 필드 충족률(정제 탈락률), 중복 스킵률, 평균 본문 길이. TOP N 후보: 카테고리별 건수, 소스별 건수, 키워드(경학 `keywords`). 인사이트 = `insights` 최신 행 |
| B6 | 차트 | 과제 요구(2종, 한글 PNG) | 카테고리별 건수(막대), 일자별 수집 추이(선, `collected_at` 기준 — 경학 `daily_counts`는 발행일 기준이라 별도 집계) + 보너스 감성 분포. 한글 폰트는 OS 자동 탐지(경학 README가 PowerShell을 안내 → Windows 팀원 존재) |
| B7 | 내보내기 포맷 | 과제 요구(CSV·JSONL·Excel 중 2+) | CSV + Excel(`openpyxl`) 필수, JSONL 추가 여부 |
| B8 | 단일 CLI 통합 방식 | 세 개의 `main.py`가 각자 argparse를 가짐 | owner `main.py`가 argparse 전체를 소유하고 각 파트는 실행 함수만 노출. 공통 옵션(`--config`, `--verbose`)·종료 코드 규칙 |
| B9 | 코드 배치 | 진성 `src/` 패키지, 경학·혜민 평면 | 평면 `app/` + `collector/`·`report/` 하위 패키지(§3) |
| B10 | 팀 저장소·브랜치·제출 형식 | 작업물이 개인 폴더·개별 저장소에 흩어짐 | 통합 저장소 위치, 브랜치 규칙, 제출물 폴더 구성 |
| B11 | 정기 실행 안내 | 보너스 | cron 예시 명령을 README에 어떤 순서로 쓸지(`fetch → clean → summarize`) |
| B12 | 조회 CLI | 보너스 `list`/`show` — 혜민 파트에 조회 함수가 없음 | 혜민에게 맡길지 owner가 쓸지 |

A 항목은 §5·§6에 권고안대로 반영해 두었다. B1·B2는 결정됐고, **B10(통합 저장소)은 코드 착수 전 owner가 정해야 하며**, 나머지 B는 owner 파트 구현 중에 정한다.

### 2-1. BBC 코리아 실측 (2026-09-09, curl 읽기 전용)

| 항목 | 실측 결과 | 설계에 미치는 영향 |
|---|---|---|
| RSS | `https://feeds.bbci.co.uk/korean/rss.xml` → 200, `text/xml`, 21건, `ttl` 15분. 항목 필드 = `title`·`description`·`link`·`guid`·`pubDate`(RFC 2822, GMT)·`media:thumbnail`. **카테고리 없음, 본문 없음** | 방법 1은 목록·메타 확보용. 본문은 방법 2로 보강. 발행시각은 GMT → KST 변환 필요(A2) |
| RSS 링크 | `.../articles/<id>?at_medium=RSS&at_campaign=rss` — 추적 파라미터 붙음 | URL 정규화(A 항목 `normalize_url`) 없이는 RSS 건과 크롤링 건이 다른 URL로 취급돼 중복이 생김. `at_*` 파라미터 제거 필수 |
| 섹션 페이지 | `https://www.bbc.com/korean/topics/<id>` — `국내 cxnyk3v82rgt` · `세계 ce71k82r6gzt` · `북한 cg726kygwz9t` · `건강·과학 cly27z42zk7t` · `문화 c8y946p5qknt` · (`비디오 cnwng7v0e54t` 제외). 각 페이지에 기사 절대 링크(`https://www.bbc.com/korean/articles/<id>`) 24개. 섹션별 RSS는 없음(`/topics/<id>/rss.xml` → 404) | 방법 2 목록 수집 = 섹션 페이지 크롤링. **카테고리는 여기서만 얻는다** |
| 기사 페이지 | `<h1 class="article-heading">` 제목 · `<main>` 안 `<p>` 본문(예시 기사 56문단·약 6,300자) · `<script type="application/ld+json">`의 `ReportageNewsArticle`에 `headline`·`datePublished`(ISO, UTC)·`about` · `<meta property="article:published_time">`. **섹션 메타 없음**. 본문 `<p>`의 class는 해시형(`css-xh3tzq`)이라 선택자로 쓰면 깨짐 | 본문 선택자 = `main p`에서 캡션·바이라인(`figure`, `data-testid="byline"`, `caption-paragraph`) 제외. 발행시각은 JSON-LD 우선, 없으면 meta. 기사 페이지에서 카테고리를 못 얻으므로 섹션 페이지 크롤링 시 부여 |
| robots.txt | `User-agent: *`에 `/korean/` 관련 Disallow 없음(검색·bitesize 등만 차단) | 크롤링 허용 범위. 단 BBC 이용약관상 비상업·학습 목적·소량·지연 준수를 README에 명시 |
| 요청량 | 섹션 5 × 24건 = 최대 120 기사 요청. 1.5초 지연이면 약 3분 | 기본 `--limit 20`, 전체 수집은 명시 옵션으로만 |

### 데이터 흐름과 실행 순서

```text
fetch     : 소스(B1) -> raw dict[] -> raw_news (append-only: collected_at·source·collection_method·raw_data)
clean     : raw_news(processed=0) -> 검증·정규화·날짜 통일·결측 처리 -> 중복 정책(skip/upsert, URL 기준) -> news
summarize : news(summary IS NULL) -> Gemini 요약 -> news.summary (+ summary_model·summarized_at)
analyze   : news(기간·카테고리, summary 있는 것) -> 20건 배치 -> reduce -> insights
sentiment : news(content) -> Gemini 감성 -> sentiment_results (news_id UNIQUE, upsert)
report    : news·insights·sentiment_results 집계 -> charts/*.png + report.md/txt + 콘솔
export    : news(필터) -> CSV / JSONL / XLSX
```

`analyze`는 `summarize` 이후에만 의미가 있다(A11).

## 5. 데이터 모델 (SQLite, 경로 = config `database.path`)

### `raw_news` — raw 저장소 (혜민 DDL + `processed`)

`id, title, url, content, published_at, source, category, collection_method, collected_at, raw_data, processed(추가·기본 0), created_at`

### `news` — clean 저장소 (혜민 DDL + 요약 메타 2컬럼)

| 컬럼 | 설명 |
|---|---|
| `id` | PK — 요약·분석·감성이 모두 이 id를 참조 |
| `raw_id` | `raw_news.id` |
| `title` NOT NULL | 공백 정규화 |
| `url` UNIQUE | 정규화 URL(스킴·호스트 소문자, 추적 파라미터 제거) — 중복 키 |
| `content` NOT NULL | 본문. 없으면 정제 탈락(혜민 규칙 유지) |
| `summary` | AI 요약 (NULL = 미요약). upsert 시 보존 규칙은 A9 |
| `summary_model` · `summarized_at` | 추가 — 품질 지표용 |
| `category` DEFAULT '기타' | B2 매핑표 적용 후 값 |
| `source` DEFAULT 'unknown' | |
| `published_at` | `YYYY-MM-DD HH:MM:SS` (A2) |
| `collected_at` | raw 승계 — 일자별 수집 추이 기준 |
| `created_at` · `updated_at` | |

`status`는 파생값: `summary IS NULL` → `clean`, 아니면 `summarized`.

### `insights` · `sentiment_results` (경학, 그대로)

`insights(id, date_from, date_to, category, article_limit, sort_order, selected_article_count, summarized_article_count, quantitative_result_json, batch_result_json, insight_result_json, created_at)` — `insight_result_json = {"trends":[3], "keywords":[6], "major_issues":[4]}`.
`sentiment_results(id, news_id UNIQUE, sentiment_result_json, created_at, updated_at)` — `{"sentiment", "score", "reason"}`.

## 9. 협업 규칙

- **Git**: 통합 저장소 1개(B10). `main`(제출본) ← `develop`(통합) ← `feat/<파트>`. `feat/*` → `develop` PR, owner 리뷰·머지. 커밋 메시지 `<파트>: <무엇을>`. `data/`·`logs/`·`output/`·`.env`·`.venv/`·`config.json` 비커밋(`config.example.json`만 커밋).
- **비밀**: API 키는 각자 `.env`. config에는 환경변수 이름만. 캡처·로그·문서 마스킹.
- **코드**: Python 3.10 문법까지(세 작업물 모두 `str | None` 사용 → 3.10 이상 확정). 타입 힌트·docstring. 출력은 CLI 결과만 `print`, 진행·오류는 `logging`(INFO 진행·WARNING 건별 실패/스킵·ERROR 단계 중단). 외부 요청 `timeout` 필수, 재시도 상한 2. `news`·`raw_news` 쓰기는 `storage.py`만, 분석·감성의 읽기와 자기 테이블은 `repository.py`. AI 호출은 `ai_client.py`만.
- **소통**: 계약 변경은 채널 → 문서 → 코드. 막히면 30분 안에 공유.

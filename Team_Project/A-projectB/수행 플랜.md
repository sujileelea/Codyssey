# 뉴스 AI 파이프라인 수행 플랜

## 0. 개요

- BBC News 코리아 뉴스를 **수집(RSS + 크롤링) → 정제 → AI 요약 → AI 인사이트 분석 → 시각화·리포트 → 내보내기**까지 하나의 CLI로 연결한 데이터 파이프라인
	- 필수 서브커맨드 6개(`fetch clean summarize analyze report export`) + 보너스 3개(`sentiment list show`)
	- 팀원 4명이 파트별로 구현한 뒤 owner가 단일 애플리케이션으로 통합

| 항목 | 내용 |
| --- | --- |
| 코드 | `app/` (Python 모듈 19개) |
| 사용법·설계·cron | `app/README.md` |
| 실행 기록·산출물 | `제출물/실행 결과.md`, `app/output/` |
| 뉴스 소스 | **BBC News 코리아** 단일 소스 — RSS 1개 + 섹션 페이지 5개 크롤링 |
| AI | **Gemini `gemini-3.5-flash-lite`** 무료 티어 (google-genai SDK) |
| 저장소 | **SQLite** `data/news.db` — `raw_news` · `news` · `insights` · `sentiment_results` |

## 2. 사용 도구

| 구분 | 도구 | 비고 |
| --- | --- | --- |
| 언어 | **Python 3.10+** (실행 3.13) | 표준 라이브러리 우선 — `argparse` `sqlite3` `logging` `csv` `json` `xml.etree` |
| 수집 방법 1 | **RSS** — `requests` + `xml.etree` | `feeds.bbci.co.uk/korean/rss.xml` → 제목·요약문·링크·발행시각 |
| 수집 방법 2 | **크롤링** — `requests` + `BeautifulSoup` | 섹션 페이지(국내·세계·북한·건강·과학·문화) → 기사 링크 → 본문·발행시각(JSON-LD)·카테고리 |
| 저장소 | **SQLite** | 영구 저장 · raw/clean 분리 · 기간·카테고리 조회와 집계 SQL |
| AI | **Gemini** `gemini-3.5-flash-lite` · `google-genai` SDK | 무료 티어 — 요약(자유 텍스트) · 인사이트·감성(JSON Schema 응답) |
| 시각화 | **matplotlib** | PNG 4종, OS별 한글 폰트 자동 탐지 |
| 내보내기 | `csv` · `json` · **openpyxl** | CSV / JSONL / XLSX |
| 설정·비밀 | `config.json` + `.env` | 소스 URL·중복 정책·모델은 config, API 키 값은 `.env`(비커밋) |
| 테스트 | **pytest** | 27건 — 정제 규칙·저장 정책·수집 파서·요약 흐름·분석/감성(Mock) |

### 선택 이유

- **BBC 코리아 단일 소스**: RSS와 섹션 페이지가 모두 공개돼 두 수집 방법을 한 사이트에서 검증 가능, `robots.txt`에 `/korean/` 차단 없음
- **RSS + 크롤링 결합**: RSS에는 카테고리·본문이 없고 크롤링만으로는 마크업 변경 위험 → 목록·메타는 RSS, 본문·카테고리는 크롤링
- **Gemini 무료 티어**: 유료 크레딧 없이 요약·분석·감성 전부 운영, JSON Schema 응답으로 파싱 실패 최소화
- **SQLite**: 의존성 없이 영구 저장·집계 SQL·UNIQUE 제약(중복 키) 확보

## 3. 아키텍처

### 데이터 흐름

```text
fetch ──▶ raw_news ──▶ clean ──▶ news ──▶ summarize ──▶ analyze ──▶ insights
  (RSS·크롤링)          (정제·중복)        (요약)          (배치→종합)      │
                                              │                              ▼
                                              ├──▶ sentiment ──▶ sentiment_results
                                              ▼
                                        report / export / list / show
```

### 모듈 구성

```text
app/
├── main.py  config.py  log.py  models.py                     # CLI · 설정 · 로깅 · 공통 모델
├── collector/  http_client.py  rss.py  crawler.py           # 수집 (타임아웃·재시도·요청 지연)
├── storage.py  cleaner.py  clean_service.py                 # 저장 · 정제
├── ai_client.py  summarizer.py                              # AI 클라이언트 · 요약
├── repository.py  insight_analyzer.py  sentiment_analyzer.py   # 인사이트 · 감성
├── report/  charts.py  report.py  exporter.py               # 차트 · 리포트 · 내보내기
├── tests/  config.json  requirements.txt  README.md
└── output/  report.md  report.txt  charts/*.png  exports/*
```

### 핵심 설계

- **raw/clean 분리**
	- `raw_news`: 수집 원본을 수집 시각·소스·수집 방법·원본 JSON과 함께 append-only 보관
	- `news`: 정제 통과 데이터만 저장, 하류 단계(요약·분석·리포트)는 clean만 참조
	- 정제 규칙 변경 시 `clean --all`로 raw에서 재생성 가능
- **두 수집 방법의 결합**
	- RSS: 목록·메타데이터 / 크롤링: 본문 전문·카테고리(섹션)
	- RSS 건의 본문은 기사 페이지 크롤링으로 보강, 카테고리는 같은 URL의 크롤링 데이터에서 보충
- **중복 처리**
	- URL 정규화(추적 파라미터 `at_*`·`utm_*` 제거) 후 `news.url` UNIQUE 기준
	- `skip`: 저장 안 함 / `upsert`: 메타 갱신, 본문이 실제로 바뀐 경우에만 요약 초기화
- **오류 처리**
	- HTTP: 타임아웃 10초 · 재시도 2회 · 요청 간 1.5초 지연 · 4xx 즉시 실패 · 건별 실패는 로깅 후 계속
	- AI: 건별 재시도 후 실패 로깅·스킵, 무료 티어 분당 한도(429)는 호출 간격 4.5초 + 대기 재시도
- **AI 클라이언트 단일화**
	- 요약·분석·감성이 `ai_client.py` 하나를 공유
	- `provider: mock`이면 키 없이 전체 파이프라인 점검 가능

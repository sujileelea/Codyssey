# 뉴스 AI 파이프라인 수행 플랜

BBC News 코리아 뉴스를 **수집 → 정제 → AI 요약 → AI 인사이트 분석 → 시각화·리포트 → 내보내기**까지 하나의 CLI로 완성한다.
팀원 4명이 파트를 나눠 각자 구현한 뒤 owner가 하나의 애플리케이션으로 통합했다. 코드는 `app/`, 실행 기록은 `제출물/실행 결과.md`, 사용법은 `app/README.md`.

## 1. 팀 역할

| 팀원 | 파트 | 담당 모듈 | 구현 내용 |
|---|---|---|---|
| **수지 (owner)** | CLI·수집·리포트·통합 | `main.py` `config.py` `log.py` `collector/` `report/` `tests/` `README.md` | argparse 서브커맨드 9개, config.json/.env 설정, logging, RSS·크롤링 수집, matplotlib 차트, 리포트(md/txt), CSV/JSONL/XLSX 내보내기, `list`/`show`, 세 파트 통합·실데이터 검증·문서 |
| **혜민** | 데이터 저장/정제 | `storage.py` `cleaner.py` `clean_service.py` | SQLite `raw_news`/`news` 스키마, raw/clean 분리 저장, 필수 필드 검증·텍스트 정규화·날짜 통일·결측 처리, 중복 정책 skip/upsert, `clean` 서브커맨드 |
| **진성** | AI 요약 | `summarizer.py` | 요약 프롬프트(3~5문장·객관·원문 외 내용 금지), `--all/--id/--unsummarized` 대상 선택, 기요약 스킵, API 실패 로깅 후 스킵, 요약 결과 저장 |
| **경학** | AI 인사이트 분석 · 감성 분석(보너스) | `ai_client.py` `repository.py` `insight_analyzer.py` `sentiment_analyzer.py` `models.py` | Gemini 공용 클라이언트(JSON Schema 응답·Mock), 20건 배치 → 종합(reduce) 인사이트(트렌드·키워드·주요 이슈), `insights` 저장·조회, 기사별 긍정/중립/부정 감성 + score + 근거 |

## 2. 사용 도구

| 구분 | 선택 | 용도 |
|---|---|---|
| 언어 | Python 3.10+ (실행 3.13) | 전체 |
| CLI | `argparse` 서브커맨드 | `fetch clean summarize analyze report export` + 보너스 `sentiment list show` |
| 수집 방법 1 | RSS — `feeds.bbci.co.uk/korean/rss.xml` (`requests` + `xml.etree`) | 제목·요약문·링크·발행시각 |
| 수집 방법 2 | 크롤링 — `requests` + `BeautifulSoup` | 섹션 페이지 5개(국내·세계·북한·건강·과학·문화)에서 기사 링크 → 기사 본문·발행시각(JSON-LD)·카테고리 |
| 저장소 | SQLite (`sqlite3`) | `raw_news` · `news` · `insights` · `sentiment_results` |
| AI | Gemini `gemini-3.5-flash-lite` 무료 티어, `google-genai` SDK | 요약(자유 텍스트), 인사이트·감성(JSON Schema 응답) |
| 시각화 | `matplotlib` | 카테고리별 뉴스 수, 일자별 수집 추이, 일자별 발행 추이, 감성 분포 (PNG, 한글 폰트 자동 탐지) |
| 내보내기 | `csv` · `json` · `openpyxl` | CSV / JSONL / XLSX |
| 설정·비밀 | `config.json` + `.env` | 소스 URL·중복 정책·모델은 config, API 키 값은 `.env`(비커밋) |
| 테스트 | `pytest` (27건) | 정제 규칙·저장 정책·수집 파서·요약 흐름·분석/감성(Mock) |

## 3. 아키텍처

```text
fetch ──▶ raw_news ──▶ clean ──▶ news ──▶ summarize ──▶ analyze ──▶ insights
  (RSS·크롤링)          (정제·중복)        (요약)          (배치→종합)      │
                                              │                              ▼
                                              ├──▶ sentiment ──▶ sentiment_results
                                              ▼
                                        report / export / list / show
```

```text
app/
├── main.py  config.py  log.py  models.py                 # CLI·설정·로깅·공통 모델
```

### 핵심 설계

- **raw/clean 분리**: 수집 원본은 `raw_news`에 수집 시각·소스·수집 방법·원본 JSON과 함께 append-only로 보관하고, 정제를 거친 데이터만 `news`에 저장한다. 정제 규칙이 바뀌면 `clean --all`로 raw에서 다시 만든다.
- **두 수집 방법의 결합**: RSS는 목록·메타데이터를, 크롤링은 본문 전문과 카테고리(섹션)를 제공한다. RSS 건의 본문은 기사 페이지 크롤링으로 보강하고, 카테고리는 같은 URL의 크롤링 데이터에서 채운다.
- **중복 처리**: URL 정규화(추적 파라미터 제거) 후 `news.url` UNIQUE 기준. `skip`은 저장 안 함, `upsert`는 갱신하되 본문이 실제로 바뀐 경우만 요약을 초기화한다.
- **오류 처리**: HTTP는 타임아웃 10초·재시도 2회·요청 간 1.5초 지연. AI는 건별 재시도 후 실패 로깅·스킵, 무료 티어 분당 한도(429)는 호출 간격 4.5초와 대기 재시도로 대응.
- **AI 클라이언트 단일화**: 요약·분석·감성이 하나의 `ai_client.py`를 공유한다. `provider: mock`이면 키 없이 전체 파이프라인을 점검할 수 있다.

## 4. 진행 단계

| 단계 | 내용 |
|---|---|
| 1. 파트별 구현 | 혜민·진성·경학이 각자 저장/정제·요약·인사이트(+감성) 모듈을 독립 저장소에서 1차 구현 |
| 2. 통합 골격 | owner가 단일 `main.py`·`config.py`·`log.py`를 만들고 세 파트를 `app/`로 통합. 공통 스키마 `news(id, title, content, summary, category, source, published_at)`와 config 구조를 하나로 맞춤 |
| 3. 수집·리포트 구현 | owner가 BBC 코리아 RSS·크롤링 수집기, 차트·리포트·내보내기, `list`/`show`, cron 안내를 구현 |
| 4. 실데이터 검증 | BBC 코리아 60건 수집 → 46건 정제 → 46건 요약 → 인사이트 2건 → 감성 46건 → 리포트·차트·내보내기까지 Gemini 실호출로 실행. 타임아웃·API 실패·키 없음·중복 정책 등 오류 경로 실측 |
| 5. 문서·제출 | README(설치·실행·설계·cron), 실행 결과 문서, 과제 개요 목표별 답변 |
